# 认知训练 · 读懂言外之意

**不是替你会聊天，而是让你看得懂、说得准。**

一个手机 App：离线刷题练判断力，**按住说话跟 AI 陪练真实对话**，脑雾来了能停。

主力形态是 Android APK（见下面的「Android App」一节），装了就能独立跑，不依赖电脑。
开发时用浏览器版本更方便改，两种都从这份代码出。

内容不分恋爱一种场景：**恋爱 / 职场 / 朋友 / 家人 / 泛社交** 五个领域，卡片页可以按领域筛选。

## 启动

```bash
cd eq-app
py -3 server.py
```

启动后终端会打印两个地址：

```
本机打开 : http://127.0.0.1:8787
手机打开 : http://192.168.x.x:8787   （需连同一 WiFi）
```

> 注意：这台机器的 `python` 命令指向的是 Python 2.7，所以**必须用 `py -3`**。
> 零第三方依赖（只用到 Python 标准库 + 你已经装好的 `openai`），不需要 pip install。

密钥从环境变量 `DEEPSEEK_API_KEY` 或上级目录的 `.env` 读取，**只在服务端使用，不会发给浏览器**。
没读到 key 也能用，只是「表达体检」和「真实复盘」两个 AI 模块会提示不可用。

（APK 里没有服务端，场景对话是网页直接调 DeepSeek——所以 key 要在 App 的 ⚙ 设置里自己填一次。）

端口默认 8787，改端口：`EQ_PORT=9000 py -3 server.py`

## 手机上怎么用：两种方式，各有取舍

**方式一 · 局域网访问（推荐，功能完整）**

手机连**同一个 WiFi**，浏览器打开终端里打印的那个地址，例如 `http://10.20.107.127:8787`。
优点：所有模块都能用，包括两个 AI 模块（密钥留在电脑上，不会泄露）。
限制：电脑得开着，手机得在同一个网络。另外**别用微信内置浏览器打开**（可能拦非标准端口），
用系统自带的浏览器（Safari / Chrome），然后「添加到主屏幕」，用起来跟原生 App 一样。

**方式二 · 单文件离线版（不依赖电脑，但没有 AI）**

```bash
py -3 build_offline.py        # 生成 认知训练-离线版.html
```

生成的单文件约 212 KB，把 HTML、样式、脚本、全部题库、图标都内联进去了，**零外部请求**。
可以走微信、邮件、网盘随便传，手机上打开就能用，进度存在手机本地。
四个离线模块（每日卡片 / 语境校准 / 心理学 / 脑雾恢复）完整可用。

> 这个文件同时也是 **APK 的内容源**：`build_apk.py` 把它当作 `assets/index.html` 打进包里。
> 所以改了网页再出 APK，顺序必须是先 `build_offline.py` 再 `build_apk.py`。

必须知道的三条限制：

1. **没有 AI 功能**。密钥绝不能写在要传出去的文件里，所以「表达体检」和「真实复盘」在离线版里
   会明确提示你去电脑上跑 `server.py`。这不是缺陷，是安全边界。
2. **iOS 上打开本地 HTML 比较绕**。Android 一般能直接在微信里「用其他应用打开」；
   iPhone 上微信收到 HTML 附件后打开会受限，通常要存到「文件」App 再想办法。
   **iOS 用户优先用方式一。**
3. **不能「添加到主屏幕」**。PWA 安装需要 HTTP 服务，本地文件不行。

改动内容后重新跑一次 `build_offline.py` 覆盖生成即可。

`verify_offline.js` 是离线版的验证脚本（`node verify_offline.js`，21 项检查）：
它会真的执行离线适配层，确认 `/api/*` 被正确拦截、AI 端点返回可读提示而不是静默失败、
错误信息里不含密钥、内联数据与源 JSON 逐字节一致（含 `scenarios.json`）、
三个脚本的加载顺序正确（`voice.js` 必须在 `app.js` 之前，否则 `EQNative` 还没定义）、
以及 `localStorage` 被浏览器禁用时会退化成内存存储而不是让 App 崩掉。

### 阶段评估：为什么关卡不能被刷过去

关卡判定有一条硬约束：**每一关的通过条件必须落在可验证的行为上，不能靠刷题量堆过去**。这不是设计洁癖，是因为一个声称能测量「情商水平」的进度条会制造虚假自信——而虚假自信正是这个 App 要治的毛病本身（把友善读成好感就是过度自信的一种）。

所以 6 关的判定分别是：

| 关 | 声明的是「你能做什么」 | 通过条件 |
|---|---|---|
| 0 摸底 | 你有一份关于自己的基线数据 | 做满 20 题（不打分、不评价，是坐标原点） |
| 1 字面与言外之意 | 你能听出她没说的那部分 | 45 题、准确率 ≥ 60%、「字面化」≤ 2 次 |
| 2 认出并压住自己的偏向 | 你的主要偏向在变小 | 误读样本 ≥ 18，且**主导偏向的占比下降 ≥ 1/3** |
| 3 接住，而不是解决 | 对方说感受时你不急着给方案 | 最近 30 题里「事务化」≤ 1 次 |
| 4 把判断变成动作 | 你的计划在现实里发生过 | 对账 ≥ 4 次，执行率 ≥ 50% |
| 5 保持 | 你在维持，不是冲刺 | 没有通过条件，也不会有 |

第 2 关是整个 App 里唯一真正的纵向进步指标：它比对**最初三分之一和最近三分之一**的误读记录，看的是同一个方向的错有没有减少。命中率可以靠重复记忆提高，偏向不行——`tools/test_stages.js` 里专门有一条断言守住这一点（「答案多但偏向没变 → 不通过」）。

第 5 关刻意没有通过条件：上面每一条描述的都是倾向，不是永久状态。压力上来、关系变长、生活变忙之后全部会退回去，所以那里看的是频率，不是高度。

### 现实任务（已按用户要求删除，这一节保留说明）

**这一节原来写的是一个已经不存在的功能：**每一关配一个现实里的小任务（追问一次 / 只接住不给建议 / 写一条预案并复看），领一个、去做、回来对账「做了 / 没做 / 没遇到那个场合」，并按执行率算关卡条件。它被用户明确要求删掉了，界面和历史记录都不再有它。

删掉之后的替代是**判局准确率**：关卡改成看「读局卡那一步（这是什么局）答得对不对」。理由写在那段代码的注释里，这里重复一遍因为它是个刻意的取舍——**做得多不等于判得准**，而判准是后面所有动作的前提，所以拿它当关卡条件比拿「做了多少件事」有意义。

保留这一节的另一个原因：**文档里留着一个已经不存在的功能，比没有文档更糟。** 下一个改这个 App 的人（包括我自己）会按它去找代码，然后找不到，然后怀疑是自己没看懂。这一条的教训和「写死清单」是同一类的——**凡是会过期的地方，要么删掉，要么明确写上「已经没有了」**。

### 「让 vs 守」：吃点亏什么时候是加分项

用户提的要求是：「可以稍微吃点亏，但是不能一直吃亏，就不能让我成为情绪的垃圾桶，但是如果一次两次其实是可以的，相当于是做一个让步、一种包容。」这个要求比「该不该忍」难得多，它要的是**判断力**。而证据恰好支持这个判断——**同一个让步行为，在两种条件下结果相反**：

- **让本身是有记录的维护手段。** Rusbult 等（1991，六个研究）把「让步」定义为：对方做出了可能具有破坏性的行为时，忍住破坏性回应、改用建设性回应。它和更高的关系满意度、承诺度、投入程度正相关。所以偶尔吃一次亏不是软弱。
- **但收益建立在它是「例外」上。** Impett 等（2010）区分了两类付出：接近型（我做这件事是为了让关系更好）和回避型（我做这件事是为了不发生冲突）。追踪研究里，接近型提升当天的和长期的满意度，回避型恰好相反——而且人们尤其不满意一个高回避型的伴侣。同一个动作，动机不同，结局相反。
- **重复到第 N 次会变成共同反刍。** 反复讨论同一个问题、反复聚焦负面感受，这个模式**同时**提高亲密度和抑郁焦虑，而且是双向的：越反刍症状越重，症状越重越反刍（Rose 2002，n=608；Rose 等 2007）。**这就是「情绪垃圾桶」的形成机制**——第一次听你在提供支持，两个人都觉得更近；听到第六次你在给循环加固，两个人都更耗。而你通常注意不到转折点，因为转折点上什么都没变，只是次数到了。

所以这批卡（`f07 f08 h06 h07 w07 w08 w09 w10 c23 c24`）的判别统一用三个问题：

> 1. 这是第一次，还是已经成了模式？
> 2. 我有没有实际损失？（偏好 vs 需要）
> 3. 对方的诉求是关系性的，还是控制性的？

覆盖了用户点名的四个场景：**朋友**（情绪垃圾桶、临时放鸽子）、**家人**（亲戚饭局、每天转养生文章）、**公司职位**（领导抢功、下班前第三次加活、下属推锅、平级同事反复求助）、**伴侣**（她冲你发火后没道歉、同一件事吵到第六次）。

**让和守的答案刻意各占一半**（7:6）。只有守的卡会教出斤斤计较的人，只有让的卡会教出老好人——两边都是这个 App 要治的毛病。`tools/test_stages.js` 里有一组断言守着这个平衡，防止后续编辑改歪。最好的几张其实是混合的，比如 `c23`：**让的是这一次的情绪，说的是你的感受——两件事都要做，但不在同一个时间做。**

配套的现实任务也有两个方向：`a_concede_once`（挑一件没实际损失的小事痛快让过去，不带情绪）和 `a_hold_once`（挑一件已经第 N 次、有实际损失的事，把次数说出来）。

### 每日计划：为什么是「跳过一次，第二次不行」

规则是 **Never Miss Twice**，来自两条实证结论：

- **Lally 等（2010）** 跟踪 96 人 12 周，原文结论是「错过一次机会对习惯养成**没有实质影响**」，但**累积的错过**会显著降低最终达到的自动化水平。所以跳过一次不是失败。
- 真正杀死习惯的不是漏掉那次，是「反正已经破了」的连锁反应（**what-the-hell effect**，来自 Marlatt & Gordon 的复发预防研究）。所以第二次必须有代价。

具体做法：当天**第一次**打开可以点「今天先跳过」；**第二次**打开就没有跳过按钮了，只能做完（4 张卡片 + 1 条微课）。达标之后闸门解除。

**卡片要「判对」才算数（2.36 改的，原来是答了就计数）。** 这条是被一次外部评审逼出来的，
而且一查就发现是真的洞：`answerCard` 里原来是 `rate(...); bumpDaily('card')`——**无条件加一**，
所以连点四张、全错的也达标、也解锁游戏，**护城河形同虚设**。而这和 App 自己的原则是矛盾的：
关卡的通过条件是「判局准确率」，上面那段也写着「做得多不等于判得准」。同一个 App 两套标准，
宽松的那套正好落在最该严的地方。

现在的判据：有读局步骤的卡看**读局那一步判对没有**；没有读局步骤的卡看动作有没有选到最好的那个。
「也算说得通，但不是首选」不算。界面和闸门浮层上都写明了这条规则，
并且会一起显示「今天答了 6 张、判对 3 张」——**规则变了就必须说出来**，否则一个不动的数字
只会让人以为 App 坏了。`tools/check_today_ui.js` 里有一节真的去答卡（走真实的 `answerCard`），
验「判错不进、判对进、闸门保持武装」——**不是复刻一份判定逻辑来测**，这一点很关键：
`tools/test_daily.js` 里的达标断言是复刻的，所以真实代码里那个无条件加一它永远看不见。

### 卡片反馈：答得「差不多」原来比答错得到的信息还少（2.37 修）

核内容时发现的一个真问题，而且它一直躲着没人发现——**grep 遍 `tools/` 找不到一处
碰过卡片反馈的断言**，所以它从来没有被守过。

现象：`「你选的这条」` 那一块的条件写成了 `!ok && bt`，而次优选项（`ok` 里列的那些，
界面上叫「也算说得通」）的 `err` 是 `正解`——`正解` 不在 `BIAS_TYPES` 里，取出来是
`undefined`，于是**整块不渲染**。后果很别扭：

- 答**错**了 → 得到「问题出在哪」+ 偏差类型 + 「往这个方向改」+ 那条选项自己的解释；
- 答**得差不多** → 只看到一句「也算说得通，但不是首选」，**它自己的解释（`why`）哪里都没显示**。

而次优是最值得讲的一类：**它是最接近的错法，差在哪才是要学的点**。数据里那条
`why` 早就写好了，只是从来没被显示过。

改法是把它拆成两支：有偏差类型 → 老样子（诊断 + 改法）；没有 → 讲清「为什么不是首选」
并说明它和首选差在哪（不是读错，是读得浅一层）。新增 `tools/check_card_feedback.js`
把答对 / 答错 / 次优三条路都钉住，并做了负向验证（把条件改回旧写法，4 条断言立刻红）。

### 读局卡多了一步：必须指一句依据（2.37）

12 张「读局」卡（`type: read`，都有 `genre`）现在的流程是三段：

1. **这是什么局？**（选一个）
2. **你凭哪一句这么判？**（从 4 条依据里挑一条，**不挑就看不到动作选项**）
3. 这一步该做什么？（4 个动作选项）

用户的原话是「**必须选一句依据才算数**」。他点名要这条，是因为他的自述里有一条
「分不清情况、直接得出结论」——而第 1 步单独存在时，人是可以凭感觉选个局就往下走的，
**局蒙对了也算过**。加上第 2 步，判局就必须落在具体证据上。

两处刻意的设计：

- **依据和判局一样要算对**，不是"选一条就行"。局判对了但依据指错，多半是蒙的
  （换一个场景就不成立了），所以那种情况不计入达标。这一条是用户选的偏严的那档；
  想放松的话改 `answerCard` 里 `counted` 那一行即可。
- **依据不是我编的，是从每张卡已有的 `state` 字段里拆出来的**——`state` 本来就写着
  「凭什么这么判」，只是原来**答完题才显示**。这一步把它提前成选项，让判断和证据
  绑在一起。干扰项一律写成**看起来合理的错读法**（多数就是这张卡本来要治的那个误读），
  否则这一步就是送分题。

数据在 `data/cards.json` 的 `clues` 字段（`[{text, ok}]`，每张 4 条、1~2 条正确）。
`tools/audit_content_quality.py` 盯着它：**有读局步骤却没有 `clues` 就是 ERR**——
那意味着用户要的这一步在那些卡上悄悄没生效，而界面上不会有任何报错。

> **补这一步时又抓到一张卡**：`r05` 是读局卡（`type: read`，`state` 里写着「这局已经
> 落地了……这是球落在地上的信号」，`err` 标签全是「该停不停 / 消极解读 / 投射」），
> **却没有 `genre` 字段**——所以它少了「这是什么局」那一步，也不会走新加的
> 「必须指一句依据」，达标判定还从「读局判对」掉到「动作选对」。线索是 README 自己
> 写着「12 张『读局』」，而 `type: read` 正好 12 张、有 `genre` 的只有 11 张。
> 已补上（局=客套收尾，依据从它自己的 `state` 拆），并加了一条不变量：
> **`type: read` ⟺ 有 `genre`**。这和 s7/s8 那个人称 bug 是同一类——
> **该有的东西悄悄没有生效，界面上不报错**。

**达标线刻意定得很低**（默认 4 + 1），宁可让你有余力去加练，不要让你因为做不完而放弃。加练**无上限、不计入达标线、也不会有任何提醒**——它的存在只是为了让你想练的时候有地方练，而不是变成第二个必须完成的指标。`tools/test_daily.js` 里有一条断言守住这个：加练再多也不能顶替必备项。

留了一条**脑雾通道**：右下角的「卡住了」在闸门里也能用。走了那条路今天记为未达标，但不会连续打断你两天。这和 App 既有的原则一致——脑雾上来时该做的是降负荷，不是忍着做完。

**提醒只在没达标的时候响。** 一个天天响、内容和状态无关的提醒，很快会被无意识忽略，等于不存在。提醒走 `AlarmManager.setAndAllowWhileIdle`，响过之后自己排明天的，重启后靠 `BOOT_COMPLETED` 重建（国产 ROM 清理得凶，自排比 `setRepeating` 可靠）。

### 护城河：达标之前拦一下游戏

这是「打游戏之前先完成」的实现，证据很具体：

- **Grüning、Riedel & Lorenz-Spreen（2023，PNAS，n=280，六周）**：在打开目标应用前插入一个摩擦延迟，并**给一个明确的放弃选项**，能让目标应用的打开次数下降 **57%**（实测：36% 的情况下用户被拦之后自己关掉了，六周内打开尝试下降 37%），而且用户的**满意度是上升的**。
- 同论文的预注册实验（n=500）发现：**单纯给提示语是无效的**，起作用的是摩擦 + 那个放弃选项。这条直接决定了设计——所以闸门是「要动手才能过」，不是一段劝说的话。

实现上有一个刻意的分工：**「该不该拦」由网页算，「怎么拦」由原生做**。网页把「今天是否达标」和「目标应用列表」推给原生（`setGate` / `scheduleReminder`），原生只负责执行。这样达标逻辑只有一份，不会两边漂移。

**为什么不用 root（重要）。** 你提到可以 root，但这个功能不需要，而且 root 是更差的选择：

| 要做的事 | 普通权限的做法 | 需要 root 吗 |
|---|---|---|
| 每天提醒 | `AlarmManager` + 通知（`POST_NOTIFICATIONS`，13+ 运行时授权） | 否 |
| 重启后提醒还在 | `RECEIVE_BOOT_COMPLETED` | 否 |
| 知道打开了哪个应用 | 无障碍服务（`GateService`） | 否 |
| 把闸门显示出来 | 用 `?gate=1` 把主界面拉到前台 | 否 |

不用 root 的理由：

1. **权限范围反而更小。** root 意味着这个 App 能做任何事；而无障碍服务配置里 `canRetrieveWindowContent="false"`，也就是它**读不到任何界面内容，只拿到一个包名**。够判断「是不是游戏」了。
2. **系统升级不会失效。** root 方案依赖具体机型的 root 实现，一次系统更新就可能全废。
3. **换台手机功能还在。** 不用重新 root。
4. **这是 Android 上的标准做法**——所有商业化的应用锁、屏幕时间工具走的都是这条路，说明它够用。

### 闸门能做到什么程度，以及为什么刻意不做更强

用户后来提了一个要求：**「让我必须得完成这个任务，第 2 次的时候；同时留一个退路，防止变成流氓软件——如果我完全放弃这个项目，把软件卸载了整个阻拦就消失。」**

第二个条件直接排除了一类做法，而且排除得有道理：

| 做法 | 能拦住吗 | 为什么不用 |
|---|---|---|
| `DevicePolicyManager.setPackagesSuspended` | 真·打不开，图标变灰 | **状态记在系统里**，卸载发起方之后可能残留，得手动去设备管理员恢复 |
| `pm disable-user` / `setApplicationEnabledSetting` | 真·打不开 | 同上，禁用状态是系统级的，卸载不还原 |
| 无障碍 + 全屏浮层（**现在用的**） | 游戏一露头就整屏盖住并把它推下去 | 全在本应用进程里，**卸载即消失，零残留** |

所以现在这版**没有任何一处写系统级状态**。这条性质不是靠自觉，`tools/test_bridge.js` 里有一条断言扫全部 Java 源码，出现 `DevicePolicyManager` / `setPackagesSuspended` / `setApplicationEnabledSetting` / `pm disable-user` 就直接失败——注释里的提及不算（扫描前会剥注释，这个误报我自己踩过两次）。

**第二次为什么能拦住。** 浮层的可跳过性由 `canSkip` 决定，而它来自网页算的「今天用没用过跳过」：
- 第一次：浮层上有「今天先跳过这次」
- 第二次：跳过按钮**整个不渲染**，而且浮层文字会说明原因
- 并且浮层是 `FLAG_LAYOUT_IN_SCREEN` + **可获焦点**的，返回键会被它吃掉，不会穿到下面的游戏

**退路只剩一个：卸载。** 浮层文字里只写这一条。

这里必须把一个容易读错的地方说清楚，因为浮层上写着「只能卸载」，很容易被理解成**前两条路已经被堵死了**——并不是：

1. 设置 → 应用 → 认知训练 → 强行停止
2. 设置 → 无障碍 → 关掉这个服务
3. **直接卸载**

第 1、2 条是**系统给用户的权力**，不是这个 App 提供的选项。任何应用都关不掉它们——能做到这一点的应用要么在利用系统漏洞，要么得用设备管理员（那正好违反「卸载即消失」）。所以这次删掉的是**提示**，不是**路径**：不告诉你，不等于不存在。真要硬堵只能靠下面的 root 深度拦截，而它依赖的 root 也可能不可用。

**卸载的代价也写在浮层上。** 进度、预案、身份陈述都在应用内部，卸载会一并清掉应用自己的数据。这个代价是刻意标出来的——一个「想退出就得全毁掉」的设计会反过来惩罚你，所以它至少得是知情的。

### 但数据不跟着走：进度备份

用户后来把这条放宽了，而且放宽的方向是对的：

> 「卸载一些残留的文本数据是可以留下来的，除非我再用清理软件给它清掉。然后所有的进程，什么代码，脚本什么的那些都要删掉，只留下文本数据。」

也就是**允许留数据，不许留能跑的东西**。前半句修掉了一个真实的设计缺陷：卸载是唯一出口，而那个出口的代价原本是「全部归零」——几个月的偏差画像、你自己写的预案，一次卸载全没。惩罚性设计在这个 App 的立场上本来就是要避免的东西。

所以现在训练记录会作为纯文本写到 **`下载/认知训练/认知训练-进度备份.json`**（`BackupStore.java`）。外部存储卸载不动它，重装之后还能捞回来。重装后本地是空的时候会问一句「发现上次卸载前的备份，要恢复吗」——**是问一句，不是静默恢复**：静默恢复会让「卸载了又装回来、数据自己全回来了」这件事看起来像软件删不干净。

几个刻意的选择：

- **自动写（节流 90 秒）+ 状态可见**，而不是一个「导出」按钮。手动导出人一定会忘，忘了的代价是丢掉几个月记录；但自动写就必须一直显示得出来，所以设置页里常驻显示写在哪、多少字节、什么时候写的。
- **写完立刻回读校验。** 卸载重装之后能不能读回同一个文件**是不保证的**——文件一定还在，但 MediaStore 的归属按包名/UID 记，重装后 UID 变了可能就不给读了。所以这里不去假装一定能读回来：读不回来就如实显示「写进去了，但读不回来……文件本身没丢」。宁可显示一个难看的真相，也不显示一个好看的空话。
- **旧版系统的权限带 `maxSdkVersion="28"`。** Android 10 起走 MediaStore，**不需要任何权限**，所以那个权限在新系统上根本不会被请求、也不会出现在权限列表里；只有 Android 9 及以下才需要它。
- **每一次写之前先删同名条目。** 不删的话 MediaStore 会自动改名成「…备份 (1).json」，用不了多久就堆出几十个副本。

**后半句（不许留能跑的东西）是这次更要紧的一半**，所以它有断言兜着，见下面「那些断言现在盯的是什么」。


### root 深度拦截：真的把游戏杀掉

浮层只是把游戏挤到后台，它还在后台活着，切回去就是一秒的事。打开深度拦截之后，检测到目标应用启动会直接 `am force-stop` 把它杀掉。

**为什么是 root 而不是 Shizuku。** 这个项目的构建是手工的（aapt2 → javac → d8），**没有依赖管理**。Shizuku 要引入它的 API 和 provider，得手工 vendor 一整套类；root 只要一句 `su -c am force-stop`。效果一样，代价差一个数量级。

`am force-stop` 只结束进程、不写持久状态，所以「卸载即消失」那条保证仍然成立——这一点和 `setPackagesSuspended` / `pm disable-user` 有本质区别，那两个会把状态记进系统。

**它的失败模式，以及为什么必须在界面上显示出来。** root 不可用（没 root / Magisk 被关 / 用户拒绝 su）时，这个功能**不会报错，只会什么都不做**。那就是我上面说过的那个最坏状态：你以为还有深度拦截，其实已经退回成只有浮层了。所以：

- 设置页的 root 状态是**三态**：`还没检测` / `可用` / `不可用`。压成布尔会让「未知」被显示成「不可用」，那是误报。
- **探测结果不跨启动保留。** root 是会变的（系统更新、换机、Magisk 被关掉）。留着一个上次的 `true`，界面就会拍胸脯说有保护、实际早就没有了。
- 只有真的探测到 root，才让你打开这个开关。
- 探测失败时**顺手把开关关掉**。留着它「开着」是最坏的状态——界面上写着有深度拦截，实际什么都没发生。
- 探测是异步的：`su` 的授权弹窗可能在等人点确认，同步等会卡住调用线程。

包名会拼进 shell 命令，所以 `RootGate` 里先做白名单正则校验再拼——来源是本地设置也一样，没有理由留这个口子。`tools/test_bridge.js` 有一条断言盯着它。

### 那些断言现在盯的是什么

「卸载即消失」这条性质不是靠自觉。`tools/test_bridge.js` 里有一组断言扫全部 Java 源码（扫描前剥注释，这个误报踩过两次）：

- 出现 `DevicePolicyManager` / `setPackagesSuspended` / `setApplicationEnabledSetting` / `pm disable-user` 就直接失败；
- **浮层上要始终写着一个真实存在的出口**——不写出口的浮层等于在说「你被困住了」，那正是要防的东西；
- 浮层不再引导用户去找前两条系统级绕开方式，但注释里保留解释（说明为什么删不掉），防止下一个人以为「没写 = 不存在」；
- root 深度拦截必须带可见状态；
- 拼进 su 命令的包名必须过白名单校验；
- **没有任何一处往磁盘写脚本或可执行文件**（`.sh` / `.bash` / `.dex` / `.apk` / `.jar` / `.so` / `.js`）——尤其不许把 root 要跑的命令写成一个脚本再执行，那样脚本就留在磁盘上了；
- **外部存储只写那一个 `.json` 文本**，root 必须继续是一次性 `ProcessBuilder` 调用、不落盘；
- 备份功能必须在位（它是「卸载不等于归零」的唯一实现，误删了就悄悄退回旧行为）。

另外还有一组浏览器端的验证（`tools/check_settings_ui.js`，需要先跑 `server.py`）：设置页在真实页面里渲染、root 三态、备份三态、「写进去了但读不回来」有单独文案、以及**重装后提示恢复**的四条路径（本地空/本地有进度/没备份文件/备份损坏）。最后这组跑的是**离线单文件版**，也就是 APK 里装的那一份。

「四个 tab 各自独立」也由断言守着（`tools/check_reported_bugs.js`）：点任意底部 tab 一定落在那一路的默认页（11 组「先去 A 子页再点 B」的组合），来回切 30 次任何 tab 下都不出现别的 tab 的页面，四个二级切换条**逐个点 DOM 按钮**且连点两次不会弹回去。同一组里还盯着「点了没反应的按钮」（`micTap` 五种不能开始听的情况都必须说话）和三类模型报错文案。

信号场另有一组（`tools/check_game.js`），盯的是**它不能被刷分**：一律答「是」或一律答「不是」时 `d′` 必须是 0；每局必须正好 10 + 10 条；`z(0.9545)`、全对 `d′≈3.38`、八成对 `d′≈1.50` 都要对得上；**同一条线索不能答第二次，一局不能记两笔成绩**（这两条各是一个真出现过的 bug）。

**怎么选要拦的应用**：设置 → 每日计划 → 「从已安装应用里挑」，读一份
**有启动图标的应用**清单（也就是你能从桌面点开的那些），搜名字或搜包名，点一下选中、
再点一下取消，选中的打勾。挑到一半退出也不会丢——点一下就立刻存了。

比原来手填包名强在哪：手打包名打错一个字母，闸门就永远不触发，而界面上**没有任何异常**，
只会让人觉得这功能没用。现在包名从「要背的东西」变成「挑一下就行」。

双开的应用、没有启动图标的系统入口不在那个清单里，那种仍然可以手填包名
（同一页下面有个折叠起来的「手动填包名」）。

**这个功能没有多要任何权限。** Android 11+ 默认看不到别的应用，通常的做法是申请
`QUERY_ALL_PACKAGES`（一个广权限，商店要单独审核）——这里刻意没有用，
只在 manifest 里声明了要查的那一个 intent（`<queries>`），
所以读到的就是「有启动图标的应用」，权限列表仍然是 7 个。
（`tools/test_bridge.js` 里有一条断言盯着权限数量与不可残留那几项。）

**开启步骤**（App 里点设置 → 每日计划，有直达按钮）：
1. 设置 → 无障碍 → 已安装的服务 → 认知训练 → 开启
2. 设置 → 应用 → 特殊权限 → 显示在其他应用上层 → 认知训练 → 允许
3. 把游戏包名填进去

目标应用包名要自己填（App 里给了查法），**默认留空是因为猜错包名会导致闸门永远不触发，而你会以为功能坏了**。两个权限缺任何一个，设置页都会明确显示是哪一个缺了——缺悬浮窗权限只会退回旧行为（把主界面拉前台），观感差很多但不至于静默失效。

### 身份陈述：为什么不由 App 下结论

用户提过一个想法：让 App 直接告诉你「你是个好男人」，说这样会潜移默化往那个方向长。**这个直觉抓到了对的东西（身份层面的改变比行为层面强），但抓错了版本，而且错的方向有实验记录。**

Sachdeva、Iliev & Medin（2009）让被试写自己身上的正面道德特质（公平、善良），结果这组人给慈善机构捐的钱**最少**；写负面特质的那组捐得最多。Jordan、Mullen & Murnighan 发现仅仅**回想**一次过去的善行，就会降低后续的亲社会意愿、提高作弊率。这个效应有名字，叫**道德许可**（Merritt、Effron & Monin 2010：「当好人使你得以作恶」）。也就是说，一个说「你是好男人」的进度条，预测的结果是让人之后表现更差——它把动机提前兑现掉了。

另一条路上有正面证据：自我肯定能降低防御（Sherman & Cohen 2002），但机制是**先稳住自我价值，人才吞得下威胁性信息**；它肯定的是「你的价值有多来源」，不是「你已经是好人」这个结论。行为关联的身份陈述之所以有动力作用，前提也是它挂在具体行为上（Oyserman 的身份动机理论）。

所以这里只做一件事：**把你自己的行为记录摆出来，让你自己写。** 形式强制成条件式——`在【什么情况下】，我会【做什么】`。条件式不是修辞要求：「我是个善良的人」是一个已完成的事实，说完就可以放下了（这正是道德许可的入口）；「有人跟我倒苦水的时候，我会先接住」是一个还在生效的标准。

`saveIdentity()` 会拦下结论式（「我是个…」）并解释原因，拦下没有情境的短句。

### 天花板声明

阶段页有一个常驻入口「看这个工具的天花板」，**不需要等通关才能看**。里面明确分两栏：这个 App 测到了什么（判断力、偏差方向、自控、执行），以及它测不到什么——你累的时候还耐不耐烦、你错了愿不愿意先认（尤其是没人看见的时候）、你觉得无聊没回报的时候还回不回家、你有没有把上面这些也当成可以刷的指标。

最后一段是：这四条比前面那四条重，而且**只能由跟你在一起的人来打分**。关于「你到底是不是个好男人」，这个 App 不会给答案——这不是谦虚，它能看到你在屏幕前的选择和你在任务里的对账，看不到你在没人看着的时候怎么选，而后者才是这件事的全部。

**改这个文件的时候请不要删掉 boundary 那一段。** 一个只有进度条、没有天花板的版本，比没有这个功能更糟。

### 底部为什么是 4 个 tab（原来是 7 个）

原来是 7 个平铺 tab，问题不是挤，是**分类维度混着**：AI 的三个功能（对话 / 体检 / 复盘）散在三处，而它们其实是同一类事（都要联网、都要填密钥）；离线训练的两个（卡片 / 校准）也散着。改成按「你要做什么」分：

| tab | 里面有什么 |
|---|---|
| **今天** | 打开就该看到的：达标进度、闸门状态、现实任务对账、当前关卡 |
| **练习** | 卡片、语境校准、微课、信号场、闲聊 |
| **AI** | 场景对话、表达体检、真实复盘——**三个在线功能全部归这里** |
| **成长** | 阶段评估、偏差画像、我的预案 |

**为什么又砍掉一层。** 上一版把「我的预案 / 偏差画像」放在卡片页里当子视图，于是卡片 → 子视图 → 卡片内容成了三层，而那两个东西其实都不是「刷卡片」，它们是对**已经积累下来的记录**做回顾——和「阶段评估」是一类事，所以并进「成长」。微课同理，它不是练习，是阅读，但为了不再多一个 tab，和练习放在一起。
另外「阶段评估」原来在成长里是唯一的入口，身份陈述和天花板声明挂在它内部；现在成长页直接给三块：阶段 / 画像 / 预案。

二级切换条统一在 `showTab()` 里注入一次（`injectSubnav`），不是在十几个渲染函数里各加一遍——这样新增子视图不用动任何已有代码。第一版在 setter 里也注入了一次，结果是切换条渲染两遍；**一个位置两处注入必然出这种事**。

**`go()` 和 `showTab()` 是两个动作，别用错。** `go(tab)` 是「从外面进这一路」，会先把该 tab 的子页归位（`TAB_HOME`：练习→卡片、AI→场景对话、成长→阶段）再画；`showTab(tab)` 是「已经在这一路里换一页」，只画不动子页。二级切换条的 setter 一律用 `showTab`。混用过一次，后果是**「表达体检」「真实复盘」两个按钮点了就弹回场景对话**——因为 `setAiSubview` 内部调的是 `go`，而 `go` 立刻把它重置回 `voice`。判断谁该用哪个只要问一句：这次点击是不是从外面进来的？

设置（密钥、提醒、闸门）留在右上角齿轮，不占 tab。

### 偏差画像与我的预案（在「成长」里）

这两个原来在卡片页顶部当子视图，现在挪进「成长」。它们不是装饰，各自对应一个研究结论。

**表面变体（每次看到的不完全一样）。** 每张卡带 4 条表面变体：换掉人（同事→同学→邻居）、场合（点外卖→点奶茶→拼单早餐）、具体细节（香菜→乳糖不耐→鸡蛋）和措辞。**考点、选项、解释、答案一个字都不动。** 为什么值得这么做：变化的是**检索线索**，不变的是**原理**——每次做的是同一类判断，但比反复看同一句话更难靠记忆过关，也更贴近现实，因为现实里没有两次一模一样的情景。

变体在 `buildQueue()` 里落地，整个一组刷完之前不会中途换场景（否则答完看解释时场景变了会很混乱）。`card.id` 不变，所以间隔重复进度和偏差画像统计仍然是同一张卡。`tools/test_content.js` 里有一条断言守着底线：**变体绝不能带自己的 options**——带了就等于换了考点。

**逐选项诊断（frame-of-reference 训练的机制）。** 答完之后不只告诉你答案，还告诉你**你选的那条为什么当时显得合理、在哪一步断了、缺哪条线索**。这不是多余的啰嗦——它是这类训练唯一被证明有效的机制。Sulsky & Day（1992）和后续一系列研究（Lundstrom 2007；Loignon 等 2017）发现，让受训者把自己的判断和专家判断对齐、并解释差异来源，才能提高判断准确性；机制研究指向"关于他人行为的推理能力"本身变强（Baret & de Kock 2018），而不是记住了题目。只公布答案，学到的是这一题；解释误读路径，学到的是**识别这一类线索**。

**偏差画像（准确率和偏差是两件事）。** 这里刻意把"命中率"和"往哪边歪"分开显示。理论上它们就是两个独立维度（West & Kenny 2011 的 truth and bias model），而后者更有用：一个人可以命中率不低，却每次都错在同一个方向上——那说明的是习惯，不是失误。画像系统统计你选错的每一次属于哪类误读，六类互相可区分：

| 误读类型 | 什么意思 |
|---|---|
| 事务化 | 她在说感受，你听成待办事项 |
| 过度解读 | 友善或中性，你读成好感 |
| 消极解读 | 中性或含糊，你读成敌意、拒绝、挑剔 |
| 投射 | 你想听什么就听到什么 |
| 字面化 | 间接表达按字面接，漏掉言外之意 |
| 乐观化 | 把不满、敷衍、带情绪的客气当成"没事" |
| 过度让步 | 该说的时候咽了，把一次可以让的事默认成长期安排 |
| 过度计较 | 小事不让，把偶发的、无心的事当成原则问题 |
| 含蓄化 | 根本没说出来——把需求留在心里期待对方发现、说一半、用玩笑盖过去 |

样本少于 6 次时会明确告诉你"现在的方向说明不了什么"——宁可不说，也不拿一个凑出来的比例误导你。

**我的预案（if-then 计划）。** 每道题答完，卡片下面有一个空框让你写自己的「如果……我就……」。这是整个 App 里证据最扎实的一个机制，所以值得单独解释，见下一节。

### 场景对话怎么玩

**四条路进同一个场景**：顶部已经替你选好一个（「今天就练这个」，本地轮换、不花钱）、
从**场景库**里点一个、自己写一句提示词让它造、或者**让 AI 按缺口造 6 个**由你挑。

**场景库**（2.32 起）＝ 我逐个写过的 **14 个** + AI 造出来**攒下来**的。
两者**按关系混在一起排**（恋爱 / 职场 / 朋友 / 家人 / 泛社交），同一个关系下面既有
现成的也有现造的，AI 造的会在卡片上标出来；每张卡还标着「练过 N 次」。
顶上那排胶囊可以按关系筛，点「看全部」会按关系分组摊开。
默认显示的那几张是**练得最少的、每个关系各一张**——不是简单取前几个（那样会是一屏恋爱，
而且新造的一直看不见）。库最多留 100 个，满了先淘汰一次都没练过的。

**造什么不是随机的，是算出来的**：每次生成前先数一遍现有场景，**缺口在哪儿就补哪儿**
（哪个关系最少、哪个难度最少），把这个缺口写成 brief 交给模型；已有场景的标题和主题
一起喂进去去重。原来那套"五个抽屉各抽一张拼起来"（谁 / 在哪 / 练什么 / 难在哪 /
最容易错）已经删掉——它会拼出「健身房的熟人 + 深夜发消息 + 必须当场答复」这种
生活里不存在的组合。

**造完还会机械地查一遍，不是求模型自觉**：标题或主题跟已有的撞就扔、同一次里同一个
关系超过 2 个就扔；不够 6 个就只补缺的（最多补一轮），补不动了就如实告诉你少了几个、
为什么。所以偶尔会出现"造好 4 个"——那不是坏了，是被去重拦下了。
（实测：一轮 6 个约 7~9 秒，连着造两轮 12 个不重样。）

**造过的都在库里，能回头再练**。刚造完那一下，批卡上直接点「练这个」；想在库里找，
按它那个关系的胶囊筛一下、或者点「看全部」。库和对话历史都只存在本机，
也会跟着那个备份 json 走（卸载重装能捞回来），**不写进安装包**。

**离开 App 再回来，对话接得上**：一进 AI 页，最上面那张卡就是「上次没聊完」——
它写清楚是哪一局、什么时候聊的、聊了几轮、对方温度多少，点一下「接着聊这一局」
就从上一句往下走。手机上被系统杀掉、划掉、放置太久重建，内存里的会话会没，
但**逐轮记录一直在存**，所以内容不丢、一句都不用重说。

**这一版起，你的话是打字发的**（输入框在对话卡片最下面，右边「发出」，回车也行）。
原来那套语音输入——免提自动收音、按住说话、语音识别——已经整块删掉了，
原因见上面「为什么不做语音输入」。**她的声音还在**：她说的每一句都会念出来，
音色、语速、音调都在设置里。

**卡住不知道说什么**的时候，输入框左边那个「提示」按钮给方向、做法、一个句式骨架、
以及最容易犯的错（本地规则，不调模型、断网也能用）；实在不行还有
「给我一句能照着说的」（点一次才调模型，给一句 30 字以内的口语示范）。

**它不是一个开放聊天。** 开放聊天里模型会配合你、顺着你说，你练的是「聊得下去」；
这里对方有立场、有没说出口的期待、也会因为你的失分而降温，你练的是
「在具体情况下做对那一个动作」。这个 App 的全部内容都指向后者，所以这里刻意
**没有**做成一个聊天框。

**随机不是图省事。** 自己选题会稳定地偏向自己已经擅长的那类——练得舒服，
但练不到短板上。所以随机池是由零件拼出来的（谁 / 在哪 / 要练什么 / 难在哪 /
最容易怎么错），再叠上你当前的偏差画像，让随机偏向你的弱项，而不是均匀随机。

### 用什么模型：这一项直接决定「像不像对话」

真实请求量出来的每轮耗时（`tools/probe_chat.py`，2.17 实测）：

| 模型 | 每轮耗时 | 推理 | 适合 |
|---|---|---|---|
| **`deepseek-chat`** | **约 1.6 秒** | 无 | **对话用这个（默认）** |
| `deepseek-flash` | 约 4.6 秒 | 1015 字 | 能用，但等得出来 |
| `deepseek-v4-pro` | **约 30 秒** | 5006 字 | 写内容可以，对话不行 |

**这两个数字之间就是「像不像豆包」的全部差别。** 对话功能本身（多轮、
每轮 JSON 字段齐全、语气和内心活动）一直是通的，实测内容也像真人
（「没多久，刚到。停车是挺难的，这附近。」），但一轮等三十秒那就不是对话了。

所以 2.17 把默认模型换成了 `deepseek-chat`，**并且迁移了已经装好的旧设置**——
这一点很关键：手机上 localStorage 里已经存着 `deepseek-v4-pro`，
只改代码里的默认值对老用户**完全没有效果**（默认值只在没存过时生效）。
设置页会把「替你换过、为什么换」写出来，想换回去点一下名字就行。

**迁移的名单要够宽，而且宽窄两头都会出问题。** 2.17 那版只认一个字符串
（`model === 'deepseek-v4-pro'`），而用户手机上存的可能是别的同一类名字
（`deepseek-reasoner` / `deepseek-r1`，带日期后缀的变体也有），那就等于没迁移——
他照样会看到「模型返回内容为空」。现在 2.22 改成一张表 + 小写包含匹配。
反过来也要留神：`deepseek-flash` 同样带推理，但它 4.6 秒能用，是设置页里
明摆着的选项，**迁移不能连它一起改掉**——那是在改用户自己的选择。
所以断言里既有「这五个该换」，也有「这两个不许动」。

另外：**一轮实测超过 8 秒时会主动提示**。判断依据是实测延迟而不是模型名——
模型可用性会变，而「这一轮等了几秒」永远是真的。如果当前已经在用最快的那个，
提示就改说网络/地址，不会去劝你换成一个你已经用的模型。

（建场景和复盘这两个更复杂的提示词也在 `deepseek-chat` 上验过：
9 字段的场景对象 1.77 秒、带嵌套数组的复盘 3.33 秒，都稳定吐合格 JSON。）

### 对方的声音（音色）和「语音包」

设置页 → 对方的声音，列出**这台手机自己的合成引擎里所有中文音色**，每一条标着
「可离线 / 需联网」「音质高/中/很高」和一个能区分彼此的短编号（ccc / ddd 这种），
可以试听。旁边还有两个按钮：**去系统里下载音色**、**打开系统语音设置**。

**为什么是「音色」而不是自带语音包。** Android 上「语音包」就是指合成引擎的
音色数据包：Google 语音服务、讯飞、华为、小米各自带几个到十几个中文音色，
很多还是可下载的。所以这个 App 自己不做音色包——那等于往安装包里塞几十 MB，
质量还不如系统自带的那几个。做的是把已有的列出来、能挑、能试听、能引导去下载。

**一个诚实的边界：这些声音都不等于真人。** 手机自带的合成引擎（不管哪个牌子）
是轻量模型，出来的是「清楚的合成音」，不是「像真人」。想接近真人只能换成云端
神经语音合成（豆包、火山、Azure、MiniMax 那类），那需要**另一个服务的另一把密钥**，
而且每句话都要联网、有延迟、按字计费。**DeepSeek 没有语音合成接口**，
所以只填 DeepSeek 的密钥是拿不到真人音的。

如果你想上云端音色，最省事的路是找一个 OpenAI 兼容的 `/audio/speech` 服务，
把地址和密钥填进设置——目前这一版还没接这条路，需要的话说一声。

另外设置页会显示**当前实际生效的音色**。有了它才能看出「选了但没生效」——
音色没下载、或者被引擎忽略时，声音会静默退回默认，而界面上的勾还打着。

### 一次练习花多少钱（实测）

用真实请求量过（做法：把 Node 侧的真发请求函数暴露给页面，让 App 自己拼的
请求真发出去，读服务端返回的 `usage`）。单位是元，按 2026-09-10 官方 Flash 系列
价格（`deepseek-chat` 属于这个系列）：空闲时段输入命中 0.02 / 未命中 1 / 输出 4，
高峰时段翻倍。

| 步骤 | 次数 | 输入 | 输出 | 缓存命中 | 空闲 | 高峰 |
|---|---|---|---|---|---|---|
| 建场景 | 1 | 422 | 150 | 61% | 0.00077 | 0.00154 |
| 对话 | 8 | 4910 | 274 | 68% | 0.00274 | 0.00549 |
| 对话后复盘 | 1 | 614 | 360 | 21% | 0.00193 | 0.00386 |
| 表达体检 | 1 | 506 | 369 | 0% | 0.00198 | 0.00396 |
| 真实复盘（出题+揭晓） | 2 | 624 | 862 | 0% | 0.00407 | 0.00814 |
| **合计** | 13 | 7076 | 2015 | 52% | **0.0115 元** | 0.023 元 |

**一个场景（建场景 + 8 轮对话 + 复盘）= 10 次调用 ≈ 0.54 分钱（空闲）／1.09 分（高峰）。**
一次把体检和真实复盘也用上 ≈ 1.15 分钱。

按月推算（只用场景对话）：一天 2 局约 **0.33 元/月**，一天 5 局约 0.82 元/月，
一天 10 局约 1.63 元/月。也就是说**就算天天练，一个月也就几毛钱。**

三条从数字里看出来的事：

- **钱主要花在输出上。** 输出是 4 元/百万，比未命中的输入贵 4 倍、比命中的贵 200 倍。
  而输入有 52% 命中缓存（对话那几轮更是 68%），因为固定的系统提示词坐在每次请求最前面，
  正好吃到前缀缓存。这个结构本来就是对的，没什么可优化。
- **一局里的固定成本是两个「收尾」调用。** 建场景 + 复盘只占输出的一半以上，
  而 8 轮对话本身才 274 个输出 token。所以**少开新局、把一局聊透最省**。
- **表达体检和真实复盘的缓存命中是 0%**，而且输出天然长（出题 396、揭晓 466 个 token）——
  这是它们贵一档的原因，不是 bug。**但这里原来的解释是错的**（2.42 更正）：原文写的是
  「因为它们每次的系统提示词都配着不同的用户内容」。前缀缓存看的是**前缀**，
  后面内容不同并不影响前面那段的复用；那两次命中 0% 只是因为它们是**第一次**调用
  （每个路径当时只跑了一次）。这个区别是要紧的：按错的那个解释，会得出「这两条路没法省」
  的错误结论——而实际上它们**有**可省的地方，见下一节。

### Token 花在哪，以及哪些地方真的能省（2.42）

用户的规矩（原话）：

> 「Token不要消耗太多就行，必要的就行，就比如说功能必须的就行，然后如果有功能，
> 可以以更省token的方式来实现，就选那个，而不是说为了token而放弃功能。」

拆成两条：**功能不为了省钱被砍掉；同一件事如果有更省的做法，必须用省的那种。**
下面是把每条路的输入拆开量过之后的账，以及动过的地方。

**量出来的账**（字符数是逐条数出来的，不是估的；中文约 1.5–1.7 字符/token）：

| 路径 | 输入里的大头 | 说明 |
|---|---|---|
| 场景对话每轮 | 系统提示词 930 字（其中 837 是固定不变的那部分） | **全 App 最省的一条路**：固定部分坐在最前面，68% 命中缓存 |
| 场景对话复盘 | 系统 635 字固定 + 本局过程 | 固定部分可跨局命中 |
| 表达体检 | 系统 818 字固定 + 用户那一句 | 固定部分占输入六成 |
| 真实复盘 | **用户粘的聊天记录**（可能两万字） | 原来这份要按全价买两遍，见下 |
| 聊天截图 OCR | **图片本身**，且 90% 是推理 token | 最贵的一条路，约 1500 推理 token/张 |

**动过三处：**

1. **真实复盘改成共用前缀（这是最大的一笔）。** 原来两次调用各自带一个不同的 system
   （出题 425 字 / 揭晓 1240 字）都放在最前面，而记录跟在后面——于是同一段记录在两次调用里
   落在**不同的 token 偏移**上，前缀缓存一次也用不上，等于按全价买了两遍。
   现在改成：system（两处逐字相同）→【聊天记录】（两处逐字相同）→ 任务说明。
   **两次调用、同一套题目、同样的输出，功能一点没少**，第二次的输入按缓存价算。
   记录越长的用户省得越多。
2. **白话模式的请求失败时不再白花第二次钱。** 接话提示和 OCR 本来就是「不要 JSON」模式，
   而原来的空返回重试会把 `response_format` 再关一次——那等于发出一个**一模一样的请求**：
   同样的输入同样的参数，不可能有不同的结果，只是多花一倍的钱和时间。
   顺带把报错里那句「第二次去掉了 response_format」改成真话（那两次其实都没带）。
3. **闲聊场景（功能照加，用最省的那条路）。** 上一版我说过「AI 闲聊场景每次要花 token，
   所以先不加」——按用户新定的规矩，这个理由是错的：**不该为了省 token 放弃功能**。
   正确的做法是选便宜的实现方式。场景对话是 App 里最省的一条路（固定系统提示词在前、
   68% 命中缓存），所以加场景**不新增任何调用**，只是多几个可选题目。
   于是 `data/scenarios.json` 加了三个弱关系闲聊场景（电梯同事 / 便利店店员 / 饭局冷场），
   它们和离线的「闲聊」那一局是配对的：**先在离线里练判断，再在这里真开口。**

**查过、但决定不动的两处**（写下来是为了别有人再"优化"一遍）：

- **给 OCR 换个更省的模型——实测没有。** 现用的 `deepseek-v4-flash-vision-exp` 是推理模型，
  抄一张截图要烧约 1500 个推理 token，看着最该换。于是拿同一张小图实测了三个模型：
  `deepseek-v4-flash-vision-exp` 能读（137 推理）、`deepseek-flash` **也能读但更贵**
  （211 推理）、`deepseek-v4-pro` **读不出来**。`/models` 里也没有任何 vision 模型。
  所以这条路的成本是**这个功能本身的价格**，不是浪费——要省只能不发图，那就是砍功能。
- **造场景的 brief 里那份"已用过的标题"清单——砍了反而更贵。** 它随着库存增长
  （`GEN_KEEP = 100`，所以是有上限的，饱和在约 2700 字），看着像明显的浪费。
  但真正的去重是**本地**做的（`screenScenes`），提示词里那份只是"劝模型别重复"；
  一旦砍掉，模型更可能造出重复的，被本地筛掉 → 触发一次**补造**调用，
  而补造那次的输出额度是 4900 token 起。**为了省一两千输入 token 去冒十倍输出 token 的风险，
  是笔亏账。**

**顺带纠正一处旧数字**：上面那张表里「建场景」的输入写的是 422，那是旧版提示词的数字；
现在是 `SCENE_SYS`(1106 字) + brief(430–493 字) ≈ **1000 tokens**，原来少报了一半多。
表里的月份推算因此偏乐观一点，但量级结论（一个月几毛钱）不变。

**新增 `tools/check_token_budget.js`（第 33 项）**，把上面三条变成断言，因为这类问题
**改回去的时候功能完全正常**——不报错、不崩、界面一模一样，只是每次多花钱，属于最难发现的一类：

- 真实复盘两次调用的 system 和记录必须**逐字相同**（前缀才认得出来），而且记录正文只能出现一次；
- 白话模式失败时不重试（1 次，不是 2 次）；带格式的那条路仍然要换形状重试（那条重试是有意义的）；
- 每条路的提示词体积有上限，涨过头就报出来。

反向验证过：把两次的 system 改得不一样，断言立刻红。

### 为什么不做语音输入（听你说话）

**这一版把语音输入整块删掉了。** 用户的原话是：

> 「做情景模拟 ai 对话的时候，等他说完话，我这边就会自动录音，停止这个功能。
> 直接把这个录音的功能删除。我直接打字算了。」

删掉的不只是"她说完就自动开麦"那个循环，而是整条输入链：免提、按住说话、
「开始说」按钮、语音识别（系统那三条路 + 2.30 才打进去的开源离线识别）、
麦克风权限、设置页里那一整块识别诊断。**她的声音保留**（TTS 合成，音色照样能选）。

为什么整条删、而不是只关掉自动那一段：只留「按住说话」的话，识别那一整套代码、
42 MB 的中文离线模型、`RECORD_AUDIO` 权限都还得背着——为一个用户明确说不要的功能
背着这些，比删掉更糟。删掉之后：安装包 **48 MB → 0.5 MB**，权限 **7 个 → 6 个**。

这一版对话页只剩一种输入方式：**打字**（输入框右边是「发出」，回车也能发）。
她说完话界面不会自己开麦，只会等你打字。

想加回来的话看 `android/vendor/README.md`——那套东西（Vosk 的 jar、两个 ABI 的
`.so`、中文模型）都还在磁盘上，不用重新下载；但那不是"改一行配置"能回来的事，
需要按 2.30 那次的顺序把原生和网页两侧一起重做，并且必须在真机上验证。

### 对话历史（每聊完一轮就存，没结束也能接着聊）

**不用先点「结束」**——每聊完一轮就落一次盘。中途切走、关掉 App、甚至忘了点结束，
这一局都在历史里躺着：列表上标「没聊完」，点「接着聊这一局」就能接着说，
前面的对话会原样画回屏幕上（给模型的上下文也一起重建，所以她是接着那个话题说的）。
点过「结束」的才有整段复盘（整体评价、反复出现的模式、要保持的、要改的 +
「下一次可以这么说」的原话、以及下一局只盯哪一件事）。

入口是 AI 页顶部那条二级导航右侧的 **📋 历史**——它在那儿，所以**这一路 tab 的
任何一页都一步可达**（原来只在「场景对话」那一页上，从体检、复盘、或者正在聊的
一局里都够不着，得先绕回那一页）。进去能看列表、
点开看某一局的全部细节，也能**单条删除**或**清空全部**——删除是两步确认
（点「删除」→ 就地变成「确定删除／取消」），因为记录只有本机一份、
删掉就真没了。

三件事是按"别丢东西"设计的：
- **存的是整局，不只存分析。** 分析是模型的话，逐轮记录才是你自己的话。
- **分析没生成出来也会存**（没密钥、没网、模型抽风都会发生）：那一局是真的
  发生过的，历史详情里给一个「现在生成分析」，随时能补。反过来丢掉整局才是可惜。
- **同一局的分析反复重生成不会多出一条**（按这一局的 id 覆盖）。
- 只留最近 **40 局**，超出的丢最旧的，界面上明说这件事，不偷偷丢。

历史跟着**备份**一起走（它就在同一个 state 里），卸载重装能从
`下载/认知训练/认知训练-进度备份.json` 里恢复。

### 信号场：为什么记分要用信号检测论，而不是「答对几道」

这是「练习」下面的第 4 个子页，也是唯一一个游戏。它的存在理由很具体：
**分辨力不是知识点，是手感**，而手感只能靠大量重复判断 + 立刻知道错在哪 + 看见自己在变。卡片练的是「想清楚」，它练的是「半秒内分辨」，两者要的东西不一样。

每轮只问一件事：**这条线索是只对你，还是她对谁都这样。** 判据只有「排他性」这一个。选它是因为它对所有情况都成立——「她喜不喜欢我」无法观察、越想越乱；「她对别人是不是也这样」再去看一眼就有答案。**把问题换成可以观察的那个，是这套训练里最省力的一步。**

**关键设计在计分上。** 题池里「不是信号」的比「是信号」的多（14 : 12），如果按答对率记分，**一律答「不是」就能拿到不错的分**，这游戏就白做了。所以用两个数字：

| 数字 | 含义 | 低了怎么办 |
|---|---|---|
| **分辨力 d′** | 你能不能看出这条和她基线不一样 | 去**加样本**——刻意观察同一个人对不同人的差别，靠想是补不上的 |
| **偏向 c** | 你更容易把事说成信号，还是更容易把事推掉 | 往「是」偏：把「我观察到的」和「我猜的」分开写；往「不是」偏：允许自己在证据够的时候说「是」 |

这两种毛病的改法正相反，混在一个答对率里就看不见了。有断言守着这个性质：**一律答「是」或一律答「不是」，d′ 都是 0**（不是高分，也不是负分——就是「没有分辨力」），而偏向 c 的符号相反。作为对照，全对时 d′≈3.38、八成对时 d′≈1.50。

顺带两个实现上的必做项，都不是可选的：
- **对数线性校正**（Hautus 1995）：命中率或虚报率恰好是 0 或 1 时，`z(0)` 是负无穷、`d′` 直接变成 NaN。而这恰恰是新手最可能的两种局面（全答是 / 全答不是），**不校正就会在最需要给反馈的时候报不出分**。
- **每局固定抽 10 条真信号 + 10 条噪声**：`d′` 的定义要求知道每类多少试次，按池子的真实比例抽会让虚报率受试次数影响，还会出现「猜多数类得分」。为了测准，这里牺牲一点真实比例是值得的。

题面分三类，缺一不可：**真信号**（12 条）、**她的基线**（8 条）、**信息不足**（6 条）。第三类最重要——它教的不是「她不喜欢你」，而是**「这条还不足以说明任何事」**。把「无法判断」当成「有信号」是最常见的一种虚报，所以这一类都要求写明「下一步该看什么」。

依据是 Brandner（2019/2022）用信号检测论重做「友善被误读成好感」那批研究后的结论：差异主要来自**分辨力**而不是一个普遍的偏向。分辨力可练，所以这个结论比「天性如此」有用，也更诚实——课程 `p15` 里两边都写了。

### 自我抽离有一条边界（而且这条证据是两边都有的）

「今日第三人称复盘」和微课 `p33` 都建立在 Grossmann & Kross（2014）和 Grossmann 等（2021，两项预注册纵向实验，N=555）之上：用**自己的名字或「你」**写反思，一个月后智慧推理和情绪复杂度都有增长。

但那是**平均效应**，而自我抽离的证据实际上是**两边都有**的，所以页面上两边都写了：

| | 研究 | 结果 |
|---|---|---|
| **反对面** | Giovanetti 等 2019（*J. Social and Clinical Psychology* 38(1):50-69；两项研究 n=104/80，连续两周每天写） | 第三人称那组的抑郁症状**多于**第一人称组和不写组，集中在**认知脆弱性偏高**的人身上；结论是「不建议用它来预防抑郁症状」 |
| **支持面** | Kross & Ayduk 2009（*J. Research in Personality* 43(5):923-927；合起五项研究，N=477） | 自我抽离的好处反而**随抑郁症状增加而变大** |

两边都没被推翻，所以既不写「放心用」也不写「别用」，只给一条可执行的规矩：**状态很差的那几天先别写，漏几天没有代价，硬写才有。**

*这一条我自己第一次写错了*：只写了反对面那一半，还写成了定论，而且是从二手博客抄的、连出处都没有。这个 App 别处在同类争议上一直在做「两边都写」（课程 `p15` 的友善误读就是这么处理的），这里没有任何理由例外。**在一个到处都是引用的项目里，突然出现一句没有出处的「有研究报告」，那本身就是个信号——它多半是抄的。**

### 背景声：为什么是「现场合成」的，以及证据到哪一步

用户的要求是「我神经比较紧张，容易焦虑，所以加入音乐或者脑波，每次进来问我要不要开，最好多来几首，设置里可以改」。现在有 **12 条音轨**：雨 / 海浪 / 风 / 溪流 / 白噪（盖环境音）/ 远处的人声 / 低频铺底 / 暖垫 / 深夜 / 双耳 4 Hz / 6 Hz / 10 Hz。

**全部由 WebAudio 现场合成，不含任何音频文件。** 两个理由：APK 现在是 0.45 MB，一首 3 分钟 mp3 就是 3–5 MB，几首就是十倍以上，还要处理版权；而这几类声音本来就能合成——噪声加滤波器就是雨和风，左右耳差几赫兹就是双耳节拍。换来的另一个好处是它真的无限长，不会有听得出来的循环接缝。

**证据必须说清楚，这块恰恰是流行说法远超证据的地方。** 界面上（设置 → 声音）和这里写的是同一套话：

- **有证据的是「安静听一会儿声音」这件事本身。** 音乐干预的元分析（累计九千多名被试）报告的焦虑下降「与部分药物干预相当」；术前焦虑的 Cochrane 综述方向也一致。所以「听点东西能松下来」站得住。
- **双耳节拍那部分要小心。** 被引最多的是 Garcia-Argibay 等 2019 的元分析（22 项研究，g≈0.45–0.58），作者自称「有希望但不算确证」。反驳的也不少：2023 年一篇脑电「脑波牵引」综述里 14 项研究只有 5 项支持牵引假说、8 项相反；2023 年一项大型居家试验里它让学习任务表现略**变差**；还有综述指出双耳节拍的皮层牵引比单耳/等时节拍**更弱**，好处可能来自唤醒度和注意而不是频率本身。
- **最要命的是混淆**：绝大多数实验把节拍**混在音乐里**放，分不清效果来自哪个。2022 年双盲试验发现 ASMR 与「双耳节拍+音乐」效果一样好；2025 年 n≈308 的随机对照发现**单耳**节拍加音乐同样能降低急性焦虑——都不支持「双耳」有什么特别之处。
- **所以实用结论只有一句**：把它当低风险的小工具用，效果主要来自「安静听一会儿」。别指望它治焦虑；焦虑到影响生活是要看医生的事。

几条硬性的使用注意（也写在界面上）：**双耳节拍必须戴耳机**——两个频率要分别进两只耳朵，外放出来会变成一个颤音，那就不是它了（所以那三条都标了「要戴耳机才成立」）；音量从低开始，上限只到 0.6；有不舒服（头晕、头痛、烦躁）就停；**有癫痫或抽搐史先问医生**——节律性声刺激属于要先问过再用的那类。

两个交互上的设计：**她说话时背景声自动压到 0.35**，因为语音被音乐盖住比反过来糟得多；**「以后别再问」必须真的生效**，否则那个启动询问就是个每次都要点掉的弹窗，结局是被讨厌。

`check_audio.js` 里有两条不是「按钮能点」的断言：把 `AudioContext` 的原型方法包起来，**查真正被创建出来的振荡器频率**（三个双耳音轨的左右耳差必须正好等于 4/6/10 Hz，且必须走 ChannelMerger 而不是普通立体声）；以及查三种噪声的**相邻采样平均差**必须满足 白 > 粉 > 棕（这一条能抓住「三种颜色算成了同一种白噪」这种错）。另外它还钉着那段证据文字不许消失——那正是最容易被当成「泼冷水」删掉的部分。

### 信号场：为什么要一直加题

一局抽 20 条（10 条真信号 + 10 条噪声）。**这个池子如果不大，游戏就废了**——玩两局就把题看完，之后靠的是记得答案，而不是分辨。它唯一想练的东西（手感）反而练不到。

当初 26 条时的实际覆盖速度是「第 2 局就看到 95%」，等于两局之后开始背答案。扩到 45 条（真信号 20 / 噪声 25）之后推迟到**第 5 局**。这是内容量直接决定训练是否成立的一个例子，`tools/expand_signal.py` 会在写回时把这个数算出来告诉你。

判据的口径没变：每条题的决定性事实**写在题面里**，所以答案唯一、不是凭感觉。可用的判据只有四个——排他性、基线、重复出现、规则被打破。

### 设置页：六个分区，一个入口

用户的原话是「可以把部分的功能全部归在一个设置里面，然后就跟大部分软件一样」。以前设置是一个长条（AI 配置 + 音色 + 语速 + 识别堆在一起），而「每日计划」「闸门挑应用」「备份」各自还有独立入口散在别的页面。现在收成一个设置页，六个分区：**声音 / AI 陪练 / 计划与提醒 / 闸门 / 数据 / 关于**。

一个刻意的取舍：**后三块的内容没有搬进来**，而是从设置里点开它们原来的面板。那些面板已经能用、也有测试盯着（`check_settings_ui` 查的就是它们），为了「看起来像设置页」把它们拆开重写，是把风险换成整洁。设置页在这里的职责是**唯一入口**，不是把所有东西复述一遍。

代价说清楚：这次重构把两处旧测试弄红了（`check_doubao` / `check_llm_errors` 一打开设置就找模型那一栏，而默认落的是「声音」）。这不是 bug，是它们假定「设置一打开就全都在」——改法是显式 `openSettings('ai')`。**「关于」里写着的版本号是一处新的漂移点**，所以 `audit_project.js` 现在也核对它和 manifest 是否一致。

### 表达体检 / 真实复盘现在走的是同一条路

这两个模块原来调的是 `/api/ai/checkup` 和 `/api/ai/replay/*` ——
也就是**只存在于电脑上 server.py 里的接口**。而 APK 里没有服务端，
离线适配层对这三个地址一律回 503，所以**在手机上它们一直是死的**：
点「体检」和「出题」都只会得到一句「这是离线单文件版，不含 AI 功能」。

现在提示词和调用都搬到前端了（`public/app.js` 里三份 `*_SYSTEM` 常量 +
`aiCheckup` / `aiReplayQuestions` / `aiReplayReveal`），统一走 `llmCall`：
**手机上是原生桥，电脑上是 `/api/proxy`**，两边行为一致、也只需要你那把密钥。
`server.py` 里那三个端点已经删掉——留着两处提示词必然会各自漂移。

### 复盘可以传聊天截图，它帮你抄成文字（2.35）

「真实复盘」里多了一个 **📷 上传聊天截图**。用微信/短信的长截图不用再手打，
识别出来填进输入框，你**看一眼、改一改**再点「出题」。

几个刻意的选择：

- **只做"图 → 文字"，不做"直接分析图"。** 用户明确说过"一般来说只需要图片识别成文字就行"。
  这样做还有一个实际好处：抄出来的字你**看得见**，抄错了当场能改——而如果模型直接从图
  出题，错在哪儿你永远不会知道。所以识别完**不会自动出题**，填完就停下。
- **长截图会切成几段发。** 聊天截图常常是 1:3、1:4 的竖长图，整张缩到模型能吃的大小之后
  字会糊掉。所以宽高比超过 2.4 就等分切开，每张单独缩到最长边 1400px，一次请求最多 3 段。
  切片之间**没有重叠**——这是个取舍：有重叠更不容易漏字，但会在拼回来的文字里留下重复的
  一整句，而重复比漏字更难发现（漏字你会觉得"这里怪怪的"，重复会被当成对方真的说了两遍）。
- **模型用视觉版**（`deepseek-v4-flash-vision-exp`，设置里可改，键是 `visionModel`），
  纯文本的对话模型**看不到图**。提示词里明确要求"看不清就写`[看不清]`，不要猜"——
  猜出来的字会伪装成真实对话，比留个标记危险得多。
- **图只在识别那一次发出去，App 不留它。** 这一点写在界面上的隐私提醒里，也写清了
  "截图本身也会发到接口"。原生的图是 `ACTION_GET_CONTENT` 拿的一次性授权，
  **刻意没有** `takePersistableUriPermission`——截图是用完就扔的东西，
  不该让这个 App 长期握着你相册里某张图的读取权。
- **失败要说清是哪一种。** 原生侧把失败分成三句不同的话：「在选择器里取消了」
  「选择器没有返回任何数据」「选择器返回了一个空地址（可能是这个图片选择器不兼容）」。
  原来只有一句笼统的「没选到图片」，在真机上根本没法判断卡在哪一步——
  这不是猜的，是踩出来的：为了知道是哪一种，我不得不重新分了三句。
- **依赖同一条密钥**：识别和出题用的是那把 DeepSeek key，所以没填 key 时按一下会提示
  「还没填 API 密钥」。这是预期行为，不是坏了。

> **视觉接口这一跳已经真跑过了（2026-09-11，用用户给的有效 key）。**
> `tools/probe_shot_ocr_live.js` 走**App 自己的代码路径**（`ocrChatShots` → `llmCall`，
> 浏览器里过 `/api/proxy`），把 `output/fake-chat.png` 那张真中文聊天截图喂进去：
> **2.4 秒返回，逐句准确**，真值关键词命中 4/4，界面正确地显示「识别完成（1 张图）」，
> 并且**换成原生那种 JSON 字符串形状再调一次也通**（同一个坑不会复发）。
> 顺便量到一件重要的事：**这个模型是推理模型，OCR 一张图会花掉约 1500 个推理 token**
> ——所以 `ocrChatShots` 里给的 4000 `max_tokens` 不是宽裕，是**必须的**；
> 我第一版探针给了 900，结果 `finish_reason=stop` 但**正文是空的**（全被推理吃了）。
> 这条和「空返回的报错要带服务端原文」是同一个坑，记在下面。
> 另外 `tools/probe_vision_models.py` 量出来：这个 key 的 `/models` 只列
> `deepseek-flash` 和 `deepseek-v4-pro`，**`deepseek-v4-flash-vision-exp` 不在列表里
> 但能用**（Vision 是未公开的实验模型名）。所以别因为"列表里没有"就换掉它——
> `deepseek-v4-pro` 对同一张图的回答是「无法读取图片内容」，它才是不能用的那个。

### 内容库的 id 是**全局名**，禁止跨文件撞名（2.38）

逐条核对内容时顺手查出来的一个**潜伏洞**，不是当下会犯的错，但犯错时不会报错：

`data/signal.json` 里 11 道 thin 题原来叫 `t01`…`t12`，而 `data/cards.json` 的
「怎么接话」卡也叫 `t01`…`t10`。**同一套名字，在两个文件里指两样东西。**

今天不出事，因为查过了：信号题的 id 从不进 `state`（信号场只记聚合统计
`{ts, d, c, hits, fa, n, maxCombo}`），而卡片 id 的每一处查表
（`CONTENT.cards.cards.find(...)` / `findIndex`）拿到的都是卡片自己发出来的 id。
**但只要哪天有人拿信号题的 id 去 cards 里查，就会静默拿到一张接话卡，而且不报错**
——这正是"最难看出来"的那一类 bug，所以我把它当错误处理，而不是当风格问题。

改动：11 道 thin 题 `t01`→`e01`…`t12`→`e12`；剩下一个 `t05` 本身是 `base` 题却用了
`t` 前缀（base 一律 `n`），改成 `n14`。改名安全的前提是**先证明没人引用**——
全仓库搜了一遍才动手，不是"看起来像命名空间"就改。

新增不变量（`tools/audit_content_quality.py` 的 `check_id_namespace`）：
**一个 id 只能出现在一个内容文件里**（跨 8 个 json 求并集查交），算 ERR；
同一种 `kind` 内前缀不统一算 WARN（`signal=x` / `base=n` / `thin=e`——它不影响正确性，
只是让人一眼看不出这是哪一类）。两个方向都做了反向验证：真的塞一个 `c01` 进
signal 里，检查确实报错；不改的话它不会自己响。

> 教训跟「信号场的检查」是同一条：**检查必须能证明它会响**。
> 一个从不报警的断言，和没有断言是一样的，而且更糟——它让人以为这块被看住了。

### 闲聊：为什么做成一局一局的「接球」（2.41）

用户的要求是「要查阅资料，要锻炼我闲聊的能力，加一些案例或者游戏，或者说其他方式你自己决定」。
这一节写清楚为什么是现在这个形状，以及依据到底是什么。

**先定训练目标。** 查下来，闲聊里被反复验证、而且**能拆成动作**的只有几件事：

| 依据 | 说的是什么 | 落到哪一步 |
|---|---|---|
| Huang 等 2017（JPSP） | 会**追问**的人更被对方喜欢；中介是「有回应」（被听见、被理解、被在意）。速度约会里多问一个问题约多换来一次二次约会。**而且人预测不到它有这个效果** | 「追问」这个动作 |
| Boothby 等 2018（Psych Science） | 聊完之后别人对你的喜欢比你估的高（liking gap）。**越害羞的人这个差越大**，而且能持续几个月 | 结果页那段话 |
| Epley & Schroeder 2014 / Sandstrom & Dunn 2014 | 跟陌生人说上话的人心情更好、归属感更强，但人们**预测**自己更喜欢安静待着 | 「弱关系」那两案 |
| Yeomans 等 2020（OBHDP） | 承认对方、不把话说过满、说想要什么——这几种说法让人更愿意继续跟你谈 | 「接住」这个动作 |

**两条边界必须一起写**（这个项目凡是写「有证据」的地方都要交代证据到哪一步）：
Huang 那篇 2025 年有一份**勘误**（报告方式上发现一些小错），审计确认全部结论不变；
另有 Kluger & Malloy（2019）对第三个研究的分析提出质疑，原作者同期发过回应——
两边对不上的是统计口径，不是「追问有没有用」。另外这些效应**量都不大**，
属于「往对的方向推一点」，不是「背下来就能变成另一个人」。这些原文都写在 `data/chat.json`
的 `evidence` 和 `caveat` 里，并且**渲染在说明页上**（有断言盯着，不许只躺在数据里）。

**为什么不只是再加一批选择题。** 现有的 84 张卡都是**单发**的：选完就结束，
看不见这句话后面会发生什么。而用户自己说的毛病是「不想事，直接得出答案」
「分不清情况，就胡说」——这两句的病根是同一个：**看不见自己这句话把局面推到了哪里**。
所以这一局的机制是：你每说一句，对方**下一句就变**。选「抢球」他的回应会变短，
选「追问」他会接着讲。把后果演出来，比再讲一遍道理有用。

这也是这个模块唯一一条最要紧的断言：`tools/check_chat.js` 会**逐案逐步**核对
「屏幕上显示的那一句 = 数据里对应分支的那一句」（6 案 × 2 步 × 2 分支）。
如果哪天有人把它改回「不管选什么下一句都一样」，这一局就退化成普通选择题，
而**界面上完全看不出来**。把预览那一句写死成 keep 分支，这条断言立刻红。

**三个刻意的设计选择：**

- **选项上不标动作名字，选完才揭。** 先标就等于送答案——人一眼看到「追问」就选它，
  什么也没练到。这和「读局必须指一句依据」是同一条思路：先做判断，再给名字。
- **「抢球 / 掉球 / 说飞」算同一类**（球都没了），但分开记。
  因为**抢球是最像热络的那一种**——对「说的比较多」的人来说，这是最需要看见的一种掉法。
  结果页因此不显示总分高低，只显示「你出手最多的是哪个动作」和掉在哪儿。
- **把 liking gap 放进结果页。** 它跟这一局直接相关：你刚才可能因为「会不会显得我很烦」
  而选了保守的那句。研究量到的正是这件事——这个估计有个稳定的偏差方向，
  所以它不能当成压住自己的理由。

**一局的形状**：4 个场合（`rounds_per_play`），一个场合 3 句，6 种动作，
每个选项都写了「这句为什么会让对方想继续／不想继续」；一个场合按保住了几个球给三种结局；
一局的成绩存 `state.chat`（接住率 + **出手习惯的累计分布**——后者比接住率有用：
接住率只说掉了几个球，出手分布说**怎么掉的**）。

### 闸门会掉：原因在系统那边，不在 App（2.39）

用户的反馈是「它容易被杀后台，就是关掉之后闸门就消失了」。查下来这句话要改两个字
——**不是被杀后台，是被强行停止**，而且这两件事的行为完全不同：

| 操作 | 进程 | 无障碍开关 | 会不会自愈 |
|---|---|---|---|
| `am kill`（普通后台/低内存清理） | **没被杀掉** | 不动 | — |
| `am force-stop`（＝划掉） | 死 | **系统自己清成 `null`**，`accessibility_enabled` 变 `0` | **不会**，等 15 秒也不回来 |
| 重启手机 | 自己起来 | 不动 | **会** |

也就是说：**已启用的无障碍服务受系统保护，普通的后台清理根本碰不到它**
（这一条推翻了「加个前台服务保活」的常规思路——加了也没用，而且白挨一个常驻通知）。
真正会杀掉它的是 force-stop，而 force-stop 会把无障碍设置一起抹掉。
麻烦在于**多数国产 ROM 把「从最近任务划掉」就实现成 force-stop**，所以划一下闸门就没了。

这件事 App 拦不住：强行停止是系统给用户的权力，`GateService` 的注释里早就写着这一条。
能做的只有两件，2.39 两件都做了。

**一、用 root 自己装回来。**（用户明确要求把 root 这个权限用起来。）
`android/res/raw/eq_gate.sh` 是一段交给 root 跑的守夜循环：每 2 秒 `pidof` 看一眼
应用在不在（便宜），不在就立刻把无障碍服务写回设置。实测**1 秒内闸门就回来**，
而且写回之后系统是**真的重新绑定**（`dumpsys accessibility` 里出现
`Bound services:{Service[label=认知训练, ...]}`）——「写进去」和「连上」是两件事，
所以这一条是实测过才算数的。

四条底线，每条都在真 Android 上跑过（不是设计意图，是结果）：

| 底线 | 为什么 | 验证 |
|---|---|---|
| 只追加、不覆盖 | `enabled_accessibility_services` 是**一整份冒号分隔的列表**，`settings put` 是整体覆盖——直接写自己那一个，会把用户其它无障碍服务全关掉 | 列表里放一个假服务，全程保留 ✓ |
| 只跑一个实例 | 重复启动会叠出一堆循环，每个都在写设置 | 连起 3 次仍是 1 个 ✓ |
| 关掉就停 | 用户在应用里关掉之后不许再插手 | 写标记文件，6 秒内退出并清锁 ✓ |
| **卸载即退出** | 用户的原始要求：卸载之后磁盘上不许剩下能跑的东西 | `pm uninstall` 后自己退出、清锁、不再写回 ✓ |

脚本用 `mkdir` 抢锁，而不是「杀掉上一个」：抢不到就让位退出，锁里记着持有者的 pid，
所以**锁过期能自愈**（被系统清掉之后，下次打开应用就把它装回去）。这条也实测过
（`kill -9` 掉、锁留着，新实例接管 ✓）。

关于「状态」又踩了一次同一类坑：应用**读不到 root 进程的 /proc**，
没法直接查那个循环还活着没有。解法是脚本每轮戳一下心跳文件，应用只读它的时间戳
——「运行中（3 秒前）」是硬证据，「我启动过它」不是。面板上因此是三态，
最要命的那一态是「**开关是开的，可它没在跑**」，它必须写出来，
因为那正是「以为有保护、其实没有」。

**二、今天页不许再说假话。** 这是本次查出来的真 bug，也是用户只能靠「真去打游戏」
才发现问题的原因。今天页那张闸门卡原来只看 `armed`，而
`armed = 想拦 && 今天没达标`——**那是意图**。系统那边明明已经把无障碍服务撤了，
卡片还在写「闸门已开、打开你指定的应用会先弹这个页面」。现在它会跟
`hasAccessibility()`（读系统实时设置）对一次账，对不上就显示「**闸门失效了**」，
并说明原因和出路。

> 这一条和「达标要判对才算」「备份要说读回来的结果」是同一类：
> **界面说的必须是事实，不是期望。** 这类 bug 既不报错也不崩，只是**说反话**，
> 所以只能用断言钉住。`tools/check_gate_watch.js` 就是这么来的：把这次改动退回去，
> 5 条断言立刻红，而且输出里能直接看到那句假话。

**注意这里改了一条原来的硬约束。** 之前 `test_bridge.js` 钉的是「**不许往磁盘写脚本**，
root 必须是一次性的 `ProcessBuilder` 调用」，理由是「那样脚本就留下了」。
防掉线必须有一个 root 下的循环，也就必须有脚本，所以判据从**形式**（有没有 `.sh`）
改成了**实质**（会不会留下）：

- 脚本只允许写在应用私有目录（`getFilesDir()`）——卸载时系统连目录一起删；
- 脚本自己每轮检查包还在不在，卸载后主动退出（有断言）；
- **外部存储那一条一个字没松**：仍然只许写那一个 `.json`，且不许是 `.sh/.dex/.apk`。

「卸载后什么都没留下」这个性质没变，变的只是它可以被实现了。这一条是用户明确要求
「都给你这么高权限了，你要有点自己的功能」之后做的，不是自己松的。

**没做、也不打算做的**（列出来是因为「别人家」确实这么干）：不往系统分区写东西、
不做开机自启（重启之后无障碍设置本来就是持久化的，用不着）、不做双进程互相拉起、
不做 1px 透明 Activity、不隐藏自己、不申请电池优化白名单（实测无关：普通后台清理
碰不到它，force-stop 又什么都挡不住）。那些是保活软件那一套，和这个项目
「卸载必须解除所有拦截」的前提冲突。

### 对话之后：评价 + 改进措施

结束一局会给你两块东西。一块是**统计**（接住了几次、没接住几次、温度、
提了几个问题、哪一句最该回头看），另一块是**复盘**——一次单独的模型调用，
把整段对话交给它，让它给：

- 整体评价（像教练，不像鼓励师）
- 一个**反复出现的模式**（这是逐轮评分看不出来的东西）
- 做对了的、下一局要保持的
- 要改的动作 + **下一次可以这么说**的原话示例
- 下一局只盯这一件事

三条硬约束写进了提示词里，因为这类输出最容易烂成鸡汤：

1. **必须引用你真正说过的原话**（所以每一轮都把你的原话记进了记录里——
   原来只存了模型判定的「你这句发出了什么信号」，转述和引用原话在教练这件事上
   差别很大）。
2. **不许恭维。** 整体不好就直说；只有一处做得好就只说那一处。
3. 每条改进必须是**一个具体动作 + 一句原话示例**，不许写「多倾听」「要有同理心」
   这类正确但没法执行的话。

复盘会把**对方的开场白**也算进去（记作「第 0 轮」）。少了它，模型判不出你的
第一句有没有接上对方说的话——而那恰恰是最容易被看出来有没有听进去的一句。

**人称跟着场景走。** 场景对象带一个 `ta`（他/她），界面上的「他的温度」「他心里的
想法」都从它取。随机场景会造出男同事、男上级，写死「她」的话那一局的对不上。
14 个手写场景里有 4 个是男性（s7 男上级、s8 男同事、s10 你爸、s11 男闺蜜），
都显式写了 `ta`；其余不带这个字段的默认「她」，行为不变。同理，扮演角色的提示词里
不再写死性别，性别由场景的 `ta` 决定。

> **这里出过一次真错（2.36 修掉）：s7 和 s8 一直是男性角色却没有 `ta`，所以界面上
> 把一个 40 岁的男上级和一个男同事叫做「她」。** 是用户看出来的——他说「那些资料库
> 你要自己核对一下，我看到有一些问题，比如说人称混乱」。查下来确实是：JSON 完全合法、

**`android/vendor/README.md`**。

踩过的两个坑值得留在这儿（都发生过，而且都看不出来）：

- **`android:extractNativeLibs="true"`。** 包里的 `.so` 只有在安装时被解到应用目录，
  JNA 那种"按名字 dlopen"才找得到。它是 false 时包是完整的、dex 是完整的、

  `build_apk.py` 会 `aapt2 dump xmltree` 把这条读回来确认。
- **构建树里的旧文件会继续被打进包。** `assets/` 是整包带进去的：模型删了代码里的引用、
  但文件还留在 `E:ndroid-buildppssets\` 时，它**照样进包**，而构建日志一切正常。
  这一条被那条 `stray` 断言抓到过一次（APK 又从 0.5 MB 变成 42 MB），
  所以现在构建脚本会主动把那个旧文件删掉。

### 交付：一条命令，而且会自动清桌面

```bash
py -3 tools/deliver.py          # 交付 + 清理（--dry 只看不删，--keep N 改保留数量）
```

它会：从 manifest 读版本号（不手抄）→ 把产物拷成 `认知训练-<版本>.apk` 和固定名的 `认知训练.apk` → 同步仓库 `android/` 里的 apk 与 manifest → **删掉桌面上更老的版本，只留最新两个**。

**用户的要求是「桌面上只留最新一次和上一次的，再之前全部删掉」。** 写成脚本而不是「记得手动删」，是因为这个项目的教训就是「凡是需要记得做某件事的设计，迟早会忘」——交付每次迭代都要做，放在脑子里必然有一天忘了，然后桌面又开始堆。

删东西之前有三道保险：只匹配 `认知训练-数字.数字.apk` 这个形状（固定名的 `认知训练.apk` 不动）；删之前确认它是真的 APK（zip 魔数 `PK` + 体积下限），同名但不是 APK 的东西会跳过并报告；`--dry` 可以先看一遍。另外它在交付前会再比一次「APK 里的 HTML == 离线版 HTML」，打错包的事故这一版刚发生过一次，最后一道门值得自己再看一眼。

### 构建链上有一环现在才被堵上：HTML 与源码的新鲜度

这条是项目自检发现的，值得单独写，因为它属于「日志一切正常但东西是旧的」那一类。

原来的校验只有一环：`build_apk.py` 会把 **APK 里的 `assets/index.html` 与 `认知训练-离线版.html` 逐字节比对**，不一致就中止。这一环本身没错，但它只保证「包里装的是那份 HTML」，**不保证「那份 HTML 是现在的源码生成的」**。

实际发生了：`public/app.js` 和 `data/curriculum.json` 被改过之后**没有重建离线版**，于是 HTML 停在前一版内容，而 APK 照常构建、字节比对通过、构建日志每一项都正常——因为 APK 确实等于那份**旧的** HTML。唯一能发现它的办法是去读界面上的字，而正常人不会去读。

现在 `build_offline.py` 会把全部输入（index.html / style.css / voice.js / app.js / icon.svg / 所有 data `*.json`，排除存档 progress.json）算一个 sha256，写进 `认知训练-离线版.src.txt`；`verify_offline.js` 重算并比对，对不上就失败并告诉你「重跑 build_offline.py」。全链于是闭合了：**源码 → HTML（已校验）→ APK（已校验）**。

两个实现上的注意点：指纹文件用 `newline="\n"` 写（Windows 上默认会把 `\n` 翻成 `\r\n`，读回来每行多个 `\r`，路径全不存在，校验会永远红而原因和源码无关）；JS 侧再 trim 一次兜底。

**这套校验原来只在 `verify_offline.js` 里，也就是"构建完之后"才生效——太晚。** 2.35 把它前移到了 `build_apk.py` 开头：构建前先重算指纹，和 `认知训练-离线版.src.txt` 里记的对不上就直接中止，并写明「先跑 `py -3 build_offline.py`」。

理由是这个坑又发生了一次，而且代价很具体：我在 `public/voice.js` 里加了一行调试输出，然后只跑了 `build_apk.py`（顺手，因为那个脚本会自己同步 assets），装进模拟器，开始查一个界面上的问题——查了很久都没进展，因为**装在手机上的 JS 是上一个版本的**，我加的那行输出根本不在包里。`verify_offline.js` 能发现，但那是收尾才跑的东西。

所以这条规矩现在是硬的：**改了 `public/` 或 `data/` 里任何东西，`build_offline.py` 必须重跑**；忘了也没关系，`build_apk.py` 会拦住。那段代码里还特意写明了它只负责**拷贝**离线版 HTML、自己不会重新生成——不然下一个人（包括我自己）还会以为"构建一次就什么都有了"。

`tools/audit_project.js` 是这次自检留下的另一个东西，它专门查这个项目**真的栽过的**那几类问题：只写不读的状态、定义了没人调用的函数、版本号在 manifest/README/PLAN 三处是否一致、产物是否新鲜、以及用户的硬约束（包里没有密钥、没有系统级状态、权限数量、外部存储调用）。它只报告不修改，退出码非零就说明有问题。**这次它一次就抓出两个只写不读的状态**（一个是被删掉的现实任务留下的 `usedAssignments`，一个是 `boundarySeen`——界面上写着「建议现在就看一遍」，而 App 其实不知道你看没看，现在接上了）。

## 这些机制是从哪来的（改内容前请先读）

这一版加的东西不是"想到一个好点子"，每一条背后都有具体的研究。列在这里，是为了以后改的时候知道**哪些设计是有约束的，不能随手改**。

**if-then 计划：为什么值得让你动手写一句。**
知道该怎么做和真的做到，中间那道坎有量化的估计：只把意图加强，行为只移动 d=.36（Webb & Sheeran）。补上「如果……我就……」之后效果大得多——Gollwitzer & Sheeran（2006）的元分析覆盖 94 个独立检验，达成目标 d=.65；2024 年更新的 642 个检验里，条件式计划（d=.43）明显优于日程式（d=.29），而且**至少预演过一次的人效果更大**。所以 App 里做了三件事：让你自己写、给你「看过了」的复看按钮、把复看次数显示出来。

有一条反直觉的硬要求：**「我就」必须是正面动作，不能是禁止式。** 写"不要辩解"的人，紧张时反而更容易辩解——否定一个念头得先把它想起来。这不是风格偏好，是在躲一个已知的逆火效应，所以 `planProblem()` 会直接拦下禁止式、台词、没有动作的空话。这套校验有 18 个用例，见 `tools/test_plan.js`。

**追问计数：为什么单独统计这个行为。**
在一项包含三次真实对话的研究里，提问多的人被对话伙伴更喜欢，追问尤其明显；速配约会里追问多的人更容易拿到第二次约会的同意（Huang 等 2017）。后续研究（Yeomans 等 2019）发现收益是累积的。机制是"被感知到的回应性"——倾听、理解、认可、在意。它特别适合放进训练，因为**人们普遍预料不到提问会让人更喜欢自己**，所以这是一个既反直觉又可直接执行的动作。判定是启发式的：带疑问词算提问，问题里出现她上一句的片段、或者用了回指（「那你当时…」「后来呢」）算追问。回指这一类必须单独认，否则"一个字都没重复"的真追问会被漏掉——`tools/test_ask.js` 里就有这个用例。

**事务化：为什么"给建议"经常是错的。**
三个实验（N=257）里，被试面对压力任务，另一个人提供支持。结果是被察觉到的支持（明说的、给建议的）**要么无效、要么让情绪反应更严重**，没被察觉到的支持才降低了情绪反应；机制是支持一旦向对方传递了"你处理不了"，就变成负担（Bolger & Amarel 2007）。所以未被请求的建议是最糟的一种。但有个关键区分：在对方**开口求助之前**默默支持更有效，**开口之后**明说才合适——决定变量是她有没有要。这也是为什么新加的 4 张「事务化」卡片，正确答案都是"先接住"，而干扰项正是"帮她分析该怎么应对"。

**友善≠好感：为什么补了一整类卡片。**
原来的 36 张里，测"友善被读成好感"的一张都没有——而这恰好是最初提出来的那个问题。它有量级：元分析发现把对方友善读成有性意味的倾向存在性别差异，平均 r≈.32（La France 等 2009）；挪威的调查里 88% 的女性报告自己的友善曾被误读成性兴趣（Bendixen 2014）。所以补了 4 张（`g05` `g06` `f05` `w06`），判定线索统一是**排他性**：她对别人是不是也这样。没有排他性就没有信号。

这里也刻意保留了反面证据：近年用信号检测论重做的研究（Brandner 2019/2022）**没能重复出"存在一个普遍偏差"**，发现差异更多来自分辨力而不是偏向。课程 `p15` 把两边都写进去了——分辨力可练，所以这个结论比"天性如此"更有用，也更诚实。

**课程里的四条新内容**（`p13`–`p17`）：追问、if-then、友善误读、准确率≠偏差，外加一条"未被请求的建议为什么更糟"。每条的 `warn` 字段都写了证据边界——量级是多少、是不是相关而非因果、样本是什么人。

## 操控识解：为什么"学 PUA"这件事我做了另一种处理

这套内容（8 条微课）的存在是因为一个合理的诉求：**PUA 那套东西里确实有对人性有用的观察，值得借鉴。** 但要分清两件事——观察和手法。我的处理是：

**讲透机制。** 推拉为什么有效（间歇性强化，和老虎机同一个原理）、冷读为什么让人信服（巴纳姆效应 + 确认偏误 + 试探修正）、三角化为什么制造压力、爱的轰炸为什么危险。这些都是真实的心理机制，讲清楚了你才看得懂。

**给出代价。** 操控策略与关系满意度、情感亲密度、承诺度都是负相关，与冲突频率和依恋焦虑正相关；男性身上较高的精神病态特质会显著拉低女性伴侣的满意度、承诺和投入，而且这个效应是**单向**的。短期有效是真的，长期账单往往由对方承担也是真的。

**重点教怎么识别别人对你用。** 冷读是"被操控"最常见的入口，所以它被放在最前面。煤气灯那一课给的是可操作的方法：不争论内容、改记录事实。

**把"思路"逐条翻译成可持续的做法。** 有一课专门做这件事（`m08`）：所谓"展示高价值"→ 研究里真正有效的是展示品格和性格（效果排序：品格 > 阅历 > 贴景机智 > 泛泛夸奖 > 性暗示调侃）；所谓"框架"→ 平等姿态说话而非争主导权；所谓"需求感"→ 不把一次结果当自我价值判决（即依恋安全感）；所谓"渐进升级"→ 社会渗透的深度互惠。**这份翻译才是唯一能长期用的部分。**

**不写成可执行的操控手册。** 研究已经给了答案：罐头式开场、性暗示调侃、忽冷忽热、制造竞争，是实证效果最差的一档，而且代价是可信度、亲密度和满意度。这个 App 不提供照着做的话术。

## 脑雾模式

右下角常驻一个「卡住了」按钮，任何页面都能一键打开。它做的事**不是让你缓一下接着学**，而是让你停下来——这两者的区别是有证据的，见下。

**四种分级手段，按状态自己挑：**

| 手段 | 什么时候用 | 依据 |
|---|---|---|
| **60 秒呼吸**（带节拍动画） | 想不动了、心里发紧、有点躁 | 斯坦福 2023 随机对照试验（114 人）：循环叹息在改善情绪和降低静息呼吸频率上，优于盒式呼吸和正念冥想。关键是呼气要长 |
| **落地 5-4-3-2-1** | 发空、发飘、像隔了一层玻璃 | 机制清楚（用感官细节占满注意力），但作为独立干预的严格证据有限——App 里也这么写的 |
| **动一下 2 分钟** | 糊、困、坐太久了 | 微休息元分析（22 样本/2335 人）：精力↑、疲劳↓，效应量约 0.35 |
| **今天先到这** | 缓了还是不行 | 同一份元分析发现微休息**对高认知负荷任务的表现没有显著提升**（d=0.16，不显著），所以在雾里继续刷题是无效功 |

**三个关键设计（不是随手加的）：**

1. **脑雾时不继续做题，而是降负荷。** 因为微休息恢复的是状态、不是高难度任务的表现。缓完之后自动切到**只读模式**（只看已有卡片的一句话原理，不答题、不计进度），而不是接着上下一道题。
2. **主动识别，不靠你自己说。** 一道题停 75 秒不动，或者连错 2 题，就会主动出现「缓一下 / 切只读」的出口——脑雾最难受的时刻恰恰是你想不起可以求助的时刻，也别让你自己判断"我是不是不行"。
3. **照顾自己算今天的活动。** 做一次恢复**不会断连击**。否则这个系统就是在惩罚你出现症状，那是最糟的激励设计。

还会自动记录每次脑雾（时间、触发、用了哪种、之后感觉），并统计最常出现的时段——这是一份可以带给医生的具体材料，比空口描述有用。

**必须说清的话**（App 里也有这一页，别跳过）：
- 脑雾是**症状**，不是诊断。常见来源：睡眠与昼夜节律、药物酒精、情绪压力、贫血/甲状腺/B12/血糖、感染后状态（长新冠、ME/CFS、POTS）、偏头痛、脑震荡、激素变化，多数是几个叠加。
- 上面四种手段**都不能治疗脑雾**，只是让你在雾里少做点无效功。没有任何补充剂被证明能治好非特异性的脑雾。
- 长新冠的 RECOVER-NEURO 试验发现，结构化认知训练和认知康复**没能跑赢对照组**的主要指标。所以这个 App 也不能宣称改善脑雾——它教沟通判断，不是脑力修复。
- 反复出现、持续很久、影响到工作或关系 → 去做医学评估，而不是靠 App。
- 如果你怀疑是感染后状态或 ME/CFS 那一类，**特别不要"用力突破"**：那类情况的特征是活动后症状加重，硬撑会让基线更差。

1. **画像只以用户的自述为准。** `data/progress.json` **不能**当成他的行为数据用——那份文件无法确认是不是他手机上的记录（开发时在模拟器里跑过测试）。曾经据此写错过一版分析，已更正。

## 设计原则（改内容之前请先读这几条）

这个 App 的方向不是「女性密码本」，恰恰相反。研究上有两条硬结论：

1. **`expected mindreading`（期待被读心）本身是个功能不良的信念**，它会损害关系满意度，触发「她不懂我 = 她不在乎我」的负面归因，进而导致冷暴力和疏远。所以：
   - 默认假设是**字面意思**，引申只是待验证的假设
   - 每道题都安排一个「她真的只是字面意思」的选项当正确答案练
   - 重点教**怎么问出来**，而不是怎么猜得准
2. **过度解读比读不懂更伤人**。演化心理学里的错误管理理论（Error Management Theory）指出，男性在信息模糊时会系统性**过度推断**女性的好感信号。所以训练里要有一半的力气花在「这里没有潜台词」上。

其他约束：

- 不教套路、不教欲擒故纵、不教冷暴力。真话是：读懂她是为了回应她，不是为了赢她。
- 反馈给**原理和方向**，不给逐字模板。研究显示纯行为脚本训练的迁移性很差（效果集中在自评量表里，6 个月后消失），而认知框架训练向未训练情境的迁移明显更好。
- **五项爱的语言**和**「90% 能预测离婚」**这两条流行理论都没通过验证，App 里没有避开它们，而是做成了两张纠错卡——你以后到处都会看到它们，得知道哪里站不住。
- 游戏化只做内部指标（连续打卡、熟练度），**不做排行榜**：研究显示排行榜会导致压力和放弃。

## 改界面之前先读这一段（2.34 起）

`public/style.css` 是**唯一一份**样式，离线单文件版就是把这一份内联进去（`build_offline.py`），
所以改这一份 = 改手机上的样子。2.34 起它上面有一层变量（`:root`），写样式**从这里取值，别写字面量**：

| 类别 | 变量 | 说明 |
|---|---|---|

| 间距（6 档） | `--sp-1` 4 / `--sp-2` 8 / `--sp-3` 12 / `--sp-4` 16 / `--sp-5` 20 / `--sp-6` 28 | 只管布局节奏（gap、卡片内边距、区块间距） |
| 圆角（4 档） | `--r-sm` 8 / `--r-md` 12 / `--r-lg` 16 / `--r-pill` 999 | 小块 / 卡片 / 大面 / 胶囊 |
| 层级（7 档） | `--z-top` 20 < `--z-tab` 30 < `--z-fab` 40 < `--z-sheet` 50 < `--z-pop` 60 < `--z-gate` 80 < `--z-toast` 90 | **顺序不能乱**：铺之前 toast 和 pop 都是 60（互相盖）、闸门 80 让 toast 永远看不见 |
| 阴影 | `--shadow-fab` `--shadow-sheet` | 两个浮标共用 |

三条硬约定：

1. **`.tabs` 是外壳，不是正文**——它的字号故意比正文小一档（`--fs-sm`）。正文提到 15px 时
   整条从 75 涨到 82px，而它下面那行 11px 副标题一个字也没变清楚。副标题**在窄屏
   （≤480px，也就是手机）上收起来**：机身只有 411 CSS px 宽，四个 tab 每个 103px，
   而副标题要 110px 以上，任何能读的字号都放不下——不收就是三条折成两行。
   那串副标题列的东西各页页内切换条上都有，不算丢信息。
2. **按钮上的字永远不换行**（`white-space: nowrap`）。中文按钮被挤窄时会一格一个字竖着排，
   比撑宽难看。行内非主按钮再加 `flex-shrink: 0`。
3. 顶部/底部留白用 `env(safe-area-inset-*)`，浮层高度用 `dvh` 不用 `vh`（键盘弹起时不被遮）。

## 几个踩过的坑（别重犯）

- **`max_tokens` 要给足，而且会截断。** 带推理的模型，推理 token 和正文**共用**这个额度。原来设 1800，被推理吃掉 1762，正文只剩 83 字节的残缺 JSON——而报出来的是「返回的不是 JSON」，完全看不出是额度问题。现在默认 3000，并且**真的会在 `finish_reason=length` 时把额度翻倍重试一次**（上限 12000），两次都截断就如实说是额度不够、并指出多半是推理吃掉了。
- **终端里 curl 传中文会乱码。** Git Bash 会把中文参数按 GBK 发出去，服务端按 UTF-8 解析就失败。调试时用文件传 body：先把 JSON 写成 UTF-8 文件，再 `curl --data-binary @file`。
- **不要把解析失败静默吞掉。** `_body()` 原来在 JSON 解析失败时返回空对象，结果「编码错误」被伪装成「字段为空」，多花了一轮才查出来。现在会明确报错。

- **`llmCall` 只解析一次。** 改成返回解析好的对象之后，调用方又 `parseJsonLoose(stripFence(raw))` 解析了一遍，把对象当字符串喂给正则，报 `t.match is not a function`。JSON 解析的边界要划在函数里面，不要两头都做。
- **`.ps1` 必须带 UTF-8 BOM 存盘。** Windows PowerShell 5.1 按 ANSI 读脚本文件，没有 BOM 时中文路径会被拆坏，报 `TerminatorExpectedAtEndOfString`。用 `encoding='utf-8-sig'` 写。
- **不要用 Python 三引号拼 Windows 路径。** 里面的 `\a` 是响铃符，会把 `E:\android-build` 写成 `E:ndroid-build`。生成脚本时用 raw string `r'''...'''`。
- **剪贴板不可靠就别硬碰。** `SetDataObject` 在别的进程占着剪贴板时抛 `ExternalException`，重试 9 次仍然失败。用户自己从桌面拖一个文件只要一秒——**优先给一条不会失败的路**，而不是替用户解决一个他没提的问题。
- **别把「设置」和「验证」放在同一个上下文里。** 曾经在设置剪贴板的同一个 shell 里读剪贴板，读到的是自己刚写的内容，误判成功。验证要在独立的一次调用里做。
- **一次校验失败不该丢掉整批结果。** 给 36 张卡生成诊断时，有一张卡的预案超长，脚本就整批中止——36 次 API 调用的结果全没了。现在原始输出先落盘缓存、plan 的问题定点重写，校验失败只中止写入、不中止重跑。
- **「不要写成可背话术」这条要求，模型会违反。** 第一版 36 条预案里有 32 条是带引号的完整台词（「我先说'听起来你有点失望'…」）。这不只是风格问题：执行意图起作用的是「情境→动作」这条链被自动化，不是让你在紧张时检索一句稿子，台词越长越不可能在那半秒里想起来。现在 `planProblem()` 会拦引号、拦「我就说」「说一句」这类结构，测试里也有对应用例。
- **写测试的价值在于它抓到了我自己没看出来的漏洞。** `我就说想吃啥就吃啥` 没有引号，第一版正则只查引号，放过去了；`多久` 不在疑问词表里，`这个方案还要改多久` 被判成"不是问题"；`那你当时怎么说的` 一个字都没重复，被判成"不是追问"——而它显然是最典型的追问。这三条都是写完测试、跑起来才暴露的。
- **内容白名单是个静默失败模式。** `boot()` 原来是 `CONTENT = { cards: ..., scenarios: ... }` 一个键一个键列的。加了 `stages.json`、接口也正常返回之后，忘了往这个清单里加，结果是 `CONTENT.stages` 一直是 null、阶段页显示「内容还没加载」，**而没有任何报错**。现在改成吸收服务端返回的每一个键（`Object.keys(j).forEach`），新增数据文件自动生效；`verify_offline.js` 里还加了一条断言守住这个机制本身。
- **身份卡片的展示门槛设错了地方。** 一开始写的是"过了第 1 关才显示"，实测发现那时用户已经做了 45 题，太晚。真正该卡的门槛是"有没有原料"——行为记录够不够写一句有依据的话，而不是"过了几关"。改成完成摸底（20 题）就出现。
- **又一个写死清单的失败模式（第三次了）。** `build_apk.py` 的 javac 只列了 `MainActivity.java`，加了 `GateService`/`ReminderReceiver`/`Prefs` 之后编译器报「找不到符号」，而**报错信息指向的是调用处**，看半天看不出是源文件没编译进来。改成自动收集 `src` 下所有 `.java`。同一个坑在 `boot()` 的内容键（v0.5）和这次的 Java 文件列表上各踩了一次——**凡是"新增文件后要记得改某处清单"的设计，迟早会忘，应该改成自动发现**。
- **渲染函数只读状态、不写状态。** 写信号场时栽在这里两次，两次都是同一句话引起的：**渲染函数会在每次重画时跑一遍**。
  - 反馈最初是「答完把按钮删掉、再把解释插进去」。看着没问题，但**中途切走再回来**会重新画出两个按钮，同一条线索能答第二次，计数就重复了。改成一整轮都从状态渲染（`answerSignal` 只改状态、调 `renderSignal`），这个问题就不存在了。
  - 结果页更隐蔽：它一边渲染一边把成绩 push 进 `state.signal.plays`。于是**打完一局、切走、再回来，同一局会被记好几笔**——玩得越多、来回切得越多，历史被灌得越假。加了个 `game.recorded` 标记。
  判据很简单：这个函数被调用两次，结果应该完全一样。不一样的就不是渲染，是操作。
- **`**` 又会从没人防的地方漏出来。** 这次是信号场的反馈页：「这条是\*\*只对你\*\*」插进了纯文本位置，而旁边的「判据」走的是 `rich()`——**同一张卡里一个对一个错**，和第 20 处 esc/rich 混用是同一个毛病。已加断言：三类题各走一遍真实渲染，扫有没有露出的 `**`。
- **写脆的断言会靠运气过。** `check_game` 里「结果页列出了四格」原来匹配的是 `/真信号|虚报|漏检/`，它能过是因为**随机抽到的某条题的解释里出现了「虚报」**——抽不到那条就红。改成按四格**实际写出来的字**断言。同一类毛病之前也出现过（数 A/B/C/D 的个数，而卡片是随机抽的）。
- **断言写错了要认，别去改数据。** 扩「语境校准」时我加了一条「只有 `revise` 才许有改法」，一跑报出 17 条违规，**全都在已有的 9 条里**。第一反应是数据脏，其实是断言错了：界面上这个字段叫「改后可以说」，对「别说」来说它的意思是「别说这句，说这句」，比只写「别说」有用得多。断言和事实冲突时，先假设是断言错了。
- **打 APK 时会用旧内容，而日志一切正常。** 见上面「构建脚本」那条：版本号、权限、签名全部正确，只有 `assets/index.html` 是 8 分钟前的老版本。现在 `build_apk.py` 自己同步并逐字节校验，`verify_offline.js` 还会断言几个关键函数确实在内联脚本里。
- **存在两份 `build_apk.py`，用仓库里那份。** `E:\android-build\build_apk.py` 是早期拷过去的，javac 那步还写死只编 `MainActivity.java`；用它构建会报「找不到符号」并指向调用处（就是上面「写死清单」那条坑），白跑一轮。**在用的那份在仓库里：`eq-app/android/build_apk.py`**，它会自动收集 `src` 下所有 `.java`。
- **断言要真的去点界面上的按钮，而不是调那个 setter。** 「二级切换条点了弹回去」这个回归，`check_ai_modules` / `check_voice_talk` 一跑就报，而如果只调 `setAiSubview('checkup')` 再看状态，**完全看不出来**——setter 本身是对的，是它内部调错了函数。凡是「用户会点的东西」，断言就点它一下。
- **静默 `return` 比报错更糟。** `micTap()` 在四种不能开始听的情况下都是干净利落地 `return`，一个字都不说。用户只能反复点，也不知道该换什么办法（下面明明有打字输入框）。现在每种原因都讲出来，并指向那条退路。写「点了没反应的按钮」之前先想清楚：不反应的时候用户怎么知道下一步做什么。
- **空返回的报错要带服务端原文。** 「模型返回了空内容，再试一次」等于没报错。真正的原因多半是带推理的模型把 `max_tokens` 吃在推理上（正文一个 token 都没剩），所以现在会带出 `reasoning_content` 的存在、点名该换成哪个模型，并附上服务端返回的头 200 字。
- **原生桥发过来的对象，到手是 `typeof 'string'`。** `js("window.__onX&&window.__onX(" + q(json) + ")")` 里的 `q()` 是 `JSONObject.quote`，它把 JSON **包成 JS 字符串字面量**——所以网页收到的是字符串，不是对象。`__onHttp` 一直是 `JSON.parse` 之后才用的，没问题；但 `__onShot` 和 `onMusicState` 直接读 `payload.ok` / 判 `typeof o !== 'object'`，于是**两处都静默失效**：不抛异常、不打日志，每次走"不成立"的兜底分支。踩到的现场是复盘传截图——真机上一直提示「没识别成功：没选到图片」，而原生日志明明是 `emit ok=true len=43195`，图读出来了、base64 也送到了。查了半天在怀疑权限、怀疑选择器、怀疑桥，最后是把 `typeof payload` 临时打到界面输入框里才看见是 `'string'`。现在统一走 `voice.js` 里的 `bridgeObj()` 归一化，`tools/test_bridge.js` 有两条静态断言（用 `q()` 发 JSON 的回调必须解字符串；不许出现 `typeof x !== 'object'` 这种"只认对象"的守卫），`tools/check_replay_shot.js` 第六节按**真实形状**真调一遍。**以后新增任何 `window.__onXxx`，第一步就是 `bridgeObj(payload)`。**
- **测试测的是"应该怎么被调用"，不是"实际怎么被调用"。** 上面那条为什么能躲过 24 项断言？因为那些断言全走 `#shotInput`（电脑那条路），等于**在测试里把 payload 当对象**交给处理函数——而真机上原生发的是字符串。两边各自都对，合起来什么都没验证到。补第六节时才想清楚：这类"接口形状"的断言，必须以**调用方的真实形状**为准，否则测试只是一份自我确认。
- **`git checkout -- <文件>` 回滚的是整个文件，不是你刚改的那一处。** 我在给 `test_bridge.js` 做"故意注入旧写法、看断言会不会红"的负向验证时，用 `git checkout -- public/app.js` 还原，结果把**整个未提交的复盘传截图界面**（按钮、`shotDone`、提示词扩展、渲染）一起清掉了——因为那些改动都还没提交。负向验证本身是对的（断言确实红了），错在"还原"的手段。补救办法这次是有的：`认知训练-离线版.html` 里内联着完整的 `app.js`，从最后一个 `<script>` 块里抠出来就是刚才那份（已按差异逐个核对后写回）。教训：**做破坏性验证前先复制一份到一边，别用 git 当"撤销上一步"**；这个仓库的未提交改动可能有很多。
- **502 不等于"对方挂了"——先怀疑自己的客户端。** 2026-09-11 我用 `urllib` 请求 GPT 中转站（`ai.ailink1.com`），所有 `chat/completions` 一律返回 `error code: 502`，但 `/v1/models` 正常。我据此写下"中转站上游故障"并改用别的模型——**这个结论是错的**，用户看了之后说「中转站没有挂，是你自己使用方法错了」。逐项隔离出来：网关把 **`User-Agent: Python-urllib/3.12`** 当爬虫挡掉了；同一个请求、同一把钥匙、同一个模型，换成 `User-Agent: curl/8.4.0` 就是 **200**。跟模型名、路由、`max_tokens` 全都无关（20/200/8000 三种都试过）。
  这条要记住的是**判断方式**：`/v1/models` 能通只证明密钥和网络没问题，不证明业务路由没问题；而"对方挂了"是一个会让我**直接放弃一条本来能用的路**的结论，所以它的举证责任很高——至少要用第二种客户端（curl）复现一次再说。同一天里，"没验证就下结论"已经是第二次了（第一次是把 `git checkout` 当成撤销上一步）。
- **一个刷屏的检查等于没有检查。** 写 `tools/audit_content_quality.py` 时，我拿「卡片的 `stage`」去比 `stages.json`，报出 **84 条**警告——全是误报：两个 `stage` 是两个概念（卡片里的是**关系阶段**：在一起磨合/共事/熟络；`stages.json` 里的是**6 个关卡**：摸底/字面与言外之意/…）。而那次**真问题只有 2 条**（人称 bug），淹没在 84 条噪声里。同一个毛病在 `audit_innerhtml.py` 的第一版又犯一次：扫全部 `innerHTML` 插值，报出 200 多条，大多是本文件里的常量拼接。两次的修法都一样——**把判据收紧到"我能说出它为什么危险"**，宁可不报也不刷屏。README 里那条"写脆的断言会靠运气过"是同一个道理的另一种表现。
- **测试测的是"应该怎么被调用"，不是"实际怎么被调用"（第二次）。** 第一次是桥的字符串形状（见上）。第二次是达标规则：`tools/test_daily.js` 里的「做满卡片 → 达标」是**复刻**了一份判定逻辑来测的，所以它测的是"我以为的规则"；而真实代码里那个 `bumpDaily('card')` 是无条件加一的，复刻的那份**永远看不见**。于是 24 项断言全绿、真机上连点四张全错也能解锁游戏。修法是 `check_today_ui.js` 里加一节，真的去点卡片（走真实的 `answerCard`），再看 `state.daily` 动没动。**凡是"复刻一份逻辑来测"的地方，都要怀疑它在测什么。**

## 已知限制

- 表达体检的分数是**方向性的，不是精确测量**。同一句话两次调用可能差一两分。看具体问题和解法，别盯着总分。
- 单次模糊信号的信息量本来就低，AI 的解读也一样。**它给的是假设，不是结论**——包括它给你的置信度。
- 在 App 里练对了不等于现实里就行。这套东西真正的闭环是：在这里练判断 → 现实里做 → 回到「真实复盘」里复盘。
- 场景对话里的「对方」是模型演的，**他/她的反应不是现实中的必然**。它训练的是你的观察和回应习惯，不是预测某一个具体的人。
- **打字比说话慢**，这是删掉语音输入换来的代价（换来的是不再有"她说完就自动开麦"那件事、以及 47 MB 的体积）。真嫌慢的话用「提示」按钮，它给的是句式骨架，改几个字就能发。
- **自带的那套离线识别只在小模型上的准确率。** 系统里有识别服务时会优先用系统的；只有在系统没有（比如这台手机）时才走自带那套。它的长句子和口音会明显更差，而且第一次用要等几十秒解模型——这两条都在界面上写明了。
- 场景对话每轮都要调一次模型（**建场景和最后的复盘各算一次**），会消耗你自己的 API 额度，一局 10 轮大约几毛钱。
- **84 张卡都是 4 个选项，但干扰项的强度差别很大**：因为 `ok` 字段收得比较松（多个读法都算「说得通」），有 **21 张卡只剩 1 个干扰项**（`ok` 写了 2 条）、**2 张剩 0 个**（`ok` 写了 3 条，等于四个选项里三个都算「说得通」）。这会让纯随机作答的期望正确率偏高，也稀释偏差画像的信号。数据列在 `data/cards.json` 里，**`ok` 为空的卡（3 个干扰项、区分度最好）是 51 张**。要收紧的话得逐张判断哪些「说得通」其实不成立，是个体力活，没有做——因为收紧会牺牲一部分「现实本来就有多种读法」的诚实。

> 这组数字原来写的是「`ok` 为空的是 11 张」——**是错的，实际 51 张**，多半是后来扩题库时没回头改。凡是写在文档里的统计数都是会过期的东西。现在 `tools/audit_content_quality.py` 会把这几个数**从数据里真算一遍再对着 README 核**，对不上就失败——和「版本号三处一致」是同一个做法。
- **偏差画像是启发式的，不是心理测量。** 误读类型由模型按固定枚举标注，会有判错的情况；追问计数是正则和二字重合的近似，报告里的措辞也写明了这一点。看趋势，别当精确指标。
- **情绪识别能力和现实社交结果之间的关联，证据远谈不上压倒性**（这一点写在课程 `p16` 里）。情境和关系知识的影响很大，所以这里练的是"结合场景判断"，不是"读脸"。
- 背景里的中文信息来自公开研究，多数是欧美样本、异性和已婚伴侣为主。跨文化适用性要自己打折扣。
- **复盘传截图已经真跑通了**（2026-09-11 用有效 key 实测：一张中文聊天截图 2.4 秒、逐句准确）。要注意的是**它是推理模型，一张图约 1500 个推理 token**，所以比纯文字对话贵一些；图只在识别那一次发出去。
